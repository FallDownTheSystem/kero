# 改动

当会话在 git 仓库中工作时，Kero 会显示它的分支和改动，让你在窗格旁审阅智能体的工作。

## 分支一览

每个窗格的标题会显示它所在的分支，以及自上次提交以来改动增加和删除的行数：`fix-login +40 −2`。进行中的合并或变基也会显示在这里。

在边栏中，如果会话所在的分支不是仓库的默认分支（比如智能体在自己的 worktree 中工作），会直接显示该分支的名称。将鼠标悬停在会话上，可以看到它的分支、相对上游领先或落后多少，以及改动了多少文件。

## 改动面板

点击窗格的分支或窗口右上角的资源管理器按钮，或按 <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>G</kbd>，即可在会话右侧打开资源管理器并显示改动。资源管理器按钮会打开上次显示的视图，资源管理器打开后它仍留在窗口角落，再点一次即可关闭。资源管理器标题栏中的**加宽资源管理器**按钮会让它占满窗格留出的全部空间，再点一次恢复。设置 `sessions-sidebar = right` 时，会话位于窗口右侧，资源管理器位于左侧，其按钮在左上角。它列出改动过的文件，以及每个文件增加和删除了多少，比较基准可以是以下之一：

- **上一轮**：会话中的智能体上一次开始工作的位置，这样你只会看到它最近一轮做了什么，而不包括之前的改动。Kero 会在智能体开始时为 worktree 拍一个快照，不会动你的暂存区和文件。
- **未提交**：上一次提交，包括未跟踪的文件。
- **分支**：当前分支从仓库默认分支分出的位置，与拉取请求中看到的一致。

每个文件下方紧跟着它的 diff，依次排列；智能体继续编辑时，diff 也会随之更新。滚动到较长的 diff 中时，文件名会固定在顶部。文件默认折叠，显示为改动文件的列表：点击文件名可以展开或折叠它的 diff。列表摘要旁的按钮会展开所有文件；有文件已展开时，则折叠所有文件。在**未提交**中，每个分区的标题上也有这个按钮。右键点击文件，可以在编辑器或编辑器窗格中打开它；把它拖到某个窗格上，就会在那里打开。拖动面板边缘可以调整宽度。

面板较窄时 diff 以统一视图显示，足够宽时则并排显示。列表摘要右侧的按钮可以在两者之间切换，`diff-layout` 设置会记住你的选择。旁边的换行按钮会按面板宽度折行显示长行，与文件视图和编辑器窗格中一样。再旁边的 **树状视图** 会按文件夹显示文件：点击文件夹可以折叠它。只包含另一个文件夹的文件夹会与它合为一行，例如 `src/app`。

### 审阅一轮改动

在 **上一轮** 中，将鼠标悬停在某处改动上，会出现两个按钮：

- **还原**：把旧的内容放回文件中。
- **保留**：将这处改动标记为已审阅，并隐藏它。

只有在会话中没有智能体正在工作时才能还原，这样就不会与智能体的编辑冲突；而且文件必须仍与 diff 所示一致。如果文件在此期间又有改动，则会重新显示。

在 **分支** 中，改动只有 **还原** 按钮：它把分支开始时文件中的行放回去，成为一处尚未提交的改动。

### 审阅评论

像在拉取请求中那样，对智能体的改动写评论，然后把你所有的评论一次发给智能体。在 **上一轮**、**未提交** 和 **分支** 中：

- 将鼠标悬停在行号上，点击出现的 **+**，即可评论该行。先点击行号，再按住 Shift 点击以选择范围，就可以一次评论所选的全部行。
- 或者将鼠标悬停在某处改动上，点击 **评论**，评论其中选中的行；没有选中行时，评论整处改动。要评论统一视图 diff 中被删除的行，就用这种方式。

在行下方的框中写下评论，点击 **评论**，或按 <kbd>⌘</kbd> <kbd>↩</kbd>（<kbd>Ctrl</kbd> <kbd>Enter</kbd>）。按 <kbd>Esc</kbd> 取消。评论会留在这些行下方，可以编辑或删除。

文件上方的栏会统计工作树中的评论数并列出它们：点击某条评论，会打开它所在的文件并定位到那一行。**发给智能体** 会把这些评论作为一条提示词粘贴到工作树中智能体所在的窗格并发送。每条评论都带有它的文件、行号和那些行的文本，所以即使行已经移动，智能体也能找到。发送后，已发送的评论就会清除。**复制为提示词** 则改为复制同一条提示词，用来交给另一个智能体；**×**（**放弃评论**）会放弃这些评论。评论会保留到 Kero 退出为止。

## 暂存与提交

在 **未提交** 中，文件分为两部分列出：下一次提交会包含的 **已暂存的改动**，以及尚未包含的 **改动**。每个文件的按钮可以暂存、取消暂存或放弃它的改动；放弃会先询问：未跟踪的文件会被删除，已删除的文件会恢复。分组标题上的按钮对其中所有文件做同样的事。**暂存所有改动** 不包含冲突，因为暂存冲突就会把它标记为已解决。

右键点击文件并选择 **添加到 .gitignore**，或右键点击树中的文件夹并选择 **将文件夹添加到 .gitignore**，即可把它添加到工作树顶层的 `.gitignore`。对于已经跟踪的文件，即使 `.gitignore` 列出了它，Git 也会继续跟踪：因此对于已跟踪的文件，或包含已跟踪文件的文件夹，Kero 会询问是否同时停止跟踪。停止跟踪的文件会在下次提交时从仓库中移除，并保留在磁盘上。

要暂存文件的一部分，将鼠标悬停在 diff 中的某处改动上，点击 **暂存**（在已暂存的改动中为 **取消暂存**）；**放弃** 会把它的旧行放回文件。只处理一处改动中的某些行时，点击它们的行号，按住 Shift 点击可选择范围，改动的按钮会变为 **暂存 N 行**、**取消暂存 N 行** 和 **放弃 N 行**。像 Git LFS 这样在存储时由 git 过滤器改变的文件，只能整个暂存。

<a id="committing"></a>

在列表下方的框中写下提交信息，点击 **提交**，或按 <kbd>⌘</kbd> <kbd>↩</kbd>（<kbd>Ctrl</kbd> <kbd>Enter</kbd>）。框中闪光图标的 **撰写信息** 会根据已暂存的内容撰写信息：由窗格中智能体对话的分叉撰写，它知道为什么做了这些改动，原对话不会改变；没有对话时，新运行 Claude Code 或 Codex。设置 `commit-message-command` 可改用其他命令撰写，它在你的 shell 中运行，提示通过标准输入传入。其中的 `{session}` 会换成窗格中智能体对话的 ID，这样你自己的启动命令也能分叉它：`cc -p --resume {session} --fork-session`。提交旁的箭头中有 **提交并推送**、**修改上次提交**、**签署** 和 **跳过钩子**。

## 分支、同步与储藏

列表上方的栏显示工作树的分支。点击它可以切换分支：输入以筛选分支，或输入新分支的名称，然后按 <kbd>Return</kbd>（<kbd>Enter</kbd>）。其中分支的菜单可以切换到它、从它新建分支、在专属工作树的会话中打开它、重命名或删除它、把它合并到你的分支，或把你的分支变基到它上面。有未提交的改动时切换，会询问先储藏它们，还是带着它们一起切换。

旁边的同步按钮会先拉取分支落后的提交，再推送领先的提交；没有上游的分支则会发布。**⋯** 菜单中有其他操作：

- **获取**、**从所有远程获取** 和 **获取并清理**。
- **拉取**（按你的 git 配置），或以合并、变基、仅快进的方式拉取。
- **推送**、**强制推送**（仅当远程分支仍是上次获取时的样子才覆盖），以及 **连同标签推送**。推送只推送这个分支，推送到它的推送目标。
- **储藏所有改动**、**储藏已暂存的改动** 和 **带信息储藏…**。
- **新建分支…**、**撤销上次提交**（其改动保持暂存）和 **刷新**。

拉取、合并和变基会先储藏未提交的改动，结束后再放回；如果它们冲突，就留在储藏中。需要密码的获取、拉取或推送会失败，并提供 **在终端中运行**，在终端中运行同一条命令，让 git 可以询问密码。

当智能体在工作树中工作时，改变文件的操作（如拉取或放弃）会先询问：**完成后** 在智能体完成后运行，**现在** 立即运行。暂存、提交和获取不会询问。

## 历史

资源管理器的 **历史** 标签页，或 <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>Y</kbd>（Windows 和 Linux 上为 <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>Y</kbd>），以图的形式显示工作树的提交：**全部** 显示所有分支的提交，**分支** 显示该分支、它的上游和默认分支的提交。本地分支和远程分支分开显示，因此同一提交上的分支和它的远程分支都会显示。尚未推送的提交会有标记。**筛选** 可以按信息、作者或哈希查找提交；文件视图中文件的菜单可以显示该文件的历史。

点击提交可查看它的文件，点击文件可查看它的 diff。文件的菜单可以像改动面板中那样打开文件，也可以用**显示文件的历史**查看它的历史。未提交的改动显示在最上方，下面是储藏，可以应用、弹出或丢弃。提交的菜单：

- **复制哈希** 和 **复制分支名称**。
- **检出**：检出该提交上的分支；没有分支时，以分离状态检出提交本身。
- **在这里新建分支…** 和 **从这里在工作树中新建会话…**。
- **把 … 合并到 …**（也可用合并提交）、**把 … 变基到 …**，以及 **把 … 交互式变基到 …**。
- **拣选**、**还原提交**，以及 **重置到这里**：软重置保留之后的改动并保持暂存，混合重置保留但不暂存，硬重置则放弃它们。

### 交互式变基

提交或分支菜单中的 **把 … 交互式变基到 …** 会列出你的分支在该提交之后的提交，最新的在上面。用菜单或按键决定每个提交怎么处理：<kbd>P</kbd> **Pick** 保留原样，<kbd>R</kbd> **Reword** 换一条新消息，<kbd>E</kbd> **Edit** 停在那里让你修改，<kbd>S</kbd> **Squash** 和 <kbd>F</kbd> **Fixup** 把它与下面的提交合并，保留两条消息或只保留下面那条，<kbd>D</kbd> **Drop** 移除它。拖动提交，或按 <kbd>Alt</kbd> <kbd>↑</kbd> 和 <kbd>Alt</kbd> <kbd>↓</kbd>，可以移动它。设为 Reword 的提交下面会打开一个面板，填写新的标题和说明。列表下方的 **提交** 和 **改动** 显示所选提交的消息和文件。

**把当前状态备份到临时分支** 会先在你的分支现在的位置建一个分支，便于回去。**变基** 会像其他变基一样先储藏未提交的改动，再按列表重放提交。遇到 Edit 的提交或冲突时会停下，**继续** 可以接着进行。包含合并提交的范围会被拉平，所以不能这样变基。

## 冲突

合并、变基、拣选或还原因冲突而停止时，栏中和提交框上方会显示出来，每个冲突的文件都列在 **改动** 中。在编辑器或终端中解决文件后点击 **标记为已解决**，或从文件的菜单中选用一方的版本：以分支命名，如 **使用 main 的版本** 或 **使用 feature 的版本**；对文件所做的编辑会丢失，所以会先询问。同一菜单中的 **在合并编辑器中打开** 会在编辑器窗格中以合并编辑器打开文件：上方并排显示两个版本，按冲突逐个对齐，下方是文件本身，可以编辑。勾选冲突上方的 **使用 main 的行** 或 **使用 feature 的行**，就会把该版本的行放进文件；两个都勾选则按勾选的顺序都放进去。下方的栏会统计剩余的冲突并在冲突之间跳转，它的菜单可以在所有冲突中使用某一版本的行，或把文件显示为纯文本。没有冲突后，**保存并标记为已解决** 会保存文件并暂存它。冲突中的文件在标记为已解决之前，在任何编辑器窗格中都这样显示。文件菜单中或提交框上方的 **让智能体解决** 会请工作树中的智能体解决这些冲突并暂存，提交留给你来做。

没有冲突后，**继续** 会继续变基、拣选或还原，**提交合并** 会用 git 准备好的信息提交合并。**中止** 会在询问后放弃该操作，回到开始前的状态。

## 在专属工作树中运行的会话

多个智能体在同一个检出目录里并行工作，会被彼此的改动绊住。**会话 › 在工作树中新建会话…**（<kbd>⌘</kbd> <kbd>⌥</kbd> <kbd>T</kbd>）会询问分支名，然后在专属的 git 工作树中启动会话：一个从仓库默认分支创建并检出新分支的文件夹。侧边栏中项目的菜单里也有这一项，用于为该项目的仓库启动会话。在没有菜单栏的 Windows 和 Linux 上，菜单栏的菜单位于侧边栏设置旁边的**菜单**按钮（⋯）中。

- 工作树位于仓库内的 `.kero/worktrees/<branch>`，Kero 通过 `.git/info/exclude`（而不是你的 `.gitignore`）忽略它。设置 `worktree-dir` 可以把工作树放到别处。
- 设置 `worktree-base = current`，可以从你所在的会话而不是默认分支创建分支。
- 会话会加入仓库所在的项目，边栏中会显示它的分支。

关闭会话时，Kero 会询问是否一并删除它的工作树：

- **没有未提交的改动：** 默认是“删除工作树”。分支若已合并会一并删除，否则会连同提交一起保留。
- **有未提交的改动：** Kero 会说明有多少文件会丢失，默认是“保留工作树”。
- **还有其他会话在这个工作树中工作：** 工作树会保留，Kero 不会询问。

在命令行中：

```sh
kero new --worktree fix-login -- claude   # 在专属工作树中、以新分支启动会话
kero new --worktree fix-login --base dev  # 从 dev 创建分支
kero close fix-login --remove-worktree    # 关闭会话并删除工作树
kero close fix-login --remove-worktree --force   # 即使有未提交的改动
```

## 文件

资源管理器的**文件**标签，或 <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>E</kbd>（Windows 和 Linux 上为 <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>E</kbd>），显示你所在窗格的工作树中的文件；不在仓库中时，显示它所在文件夹的文件。在远程主机上，显示的是该主机的文件。

点击文件夹，或按 <kbd>→</kbd> 和 <kbd>←</kbd>，展开或折叠它。点击文件，它会在树下方打开，按其语言高亮，并可直接编辑：<kbd>⌘</kbd> <kbd>S</kbd>（<kbd>Ctrl</kbd> <kbd>S</kbd>）保存，并保留原有的换行符。编辑过的文件在你查看其他文件时保持打开，并标为未保存。文件上方的换行按钮会按视图宽度折行显示长行；Markdown 文件的 **预览 Markdown** 会按渲染后的样子显示它。图片以图片显示；二进制文件和超过 4 MB 的文件不会打开。关闭 `files-preview` 后，点击只会选中文件，可从其菜单中的**预览**在树下方打开它。要把文件留在终端旁边，可在[编辑器窗格](./panes.md#editor-panes)中打开它。

树下方的 **新建文件…** 和 **新建文件夹…** 按钮可在所选文件夹中，或所选文件所在的文件夹中创建文件或文件夹。输入名称或类似 `src/util/new.go` 的路径，然后按 <kbd>Return</kbd>（<kbd>Enter</kbd>）创建；按 <kbd>Esc</kbd> 可取消。新文件会在树下方打开。其他按钮可刷新文件树或折叠其中的文件夹。文件夹菜单可在该文件夹中新建文件或文件夹，也可选择 **在此新建终端**，在此处打开终端。

按钮之间的 **筛选** 栏会在整个文件夹（包括已折叠的文件夹）中按名称查找文件和文件夹，并在它们所在的文件夹中显示。输入斜杠时改为按路径匹配，如 `src/main`。git 忽略的文件夹（如 `node_modules`）可按名称找到，但不会搜索其内容。按 <kbd>↓</kbd> 或 <kbd>Return</kbd>（<kbd>Enter</kbd>）转到找到的第一个文件，按 <kbd>Esc</kbd> 清除筛选，并在完整的树中显示所选文件。

保存只在文件仍是你打开时的样子时才写入。如果之后智能体或其他程序改动了它，Kero 会提示你，由你选择**重新载入**（放弃你的编辑）或**覆盖**。在你没有编辑时，它会跟随磁盘上的改动。

双击文件或右键点击它，可在编辑器中打开：即 `editor` 设置（如 `code` 或 `zed`），未设置时用系统打开该文件的应用。设置 `files-double-click = pane` 时，双击会在编辑器窗格中打开。除非关闭 `files-hidden`，否则会显示点文件。文件夹的菜单同样可在编辑器中打开文件夹（未设置时用系统打开文本文件的应用）。菜单中还可以在窗格中打开、用其他应用打开、在文件资源管理器或访达中显示，以及复制路径或相对于工作树的路径。

### 前往文件

**会话 › 前往文件…**（<kbd>⌘</kbd> <kbd>⇧</kbd> <kbd>N</kbd>，Windows 和 Linux 上为 <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>N</kbd>）会按名称查找你所在窗格的工作树中的文件，依次输入名称中的字母即可：`usvc` 能找到 `user_service.go`。名称的匹配排在路径之前；输入斜杠则只匹配路径，如 `src/main`。按 <kbd>Return</kbd>（<kbd>Enter</kbd>）会在编辑器窗格中打开文件，与文件视图中的文件打开方式相同；按 <kbd>⌘</kbd> <kbd>↩</kbd>（<kbd>Ctrl</kbd> <kbd>Enter</kbd>）则在新窗格中打开。在仓库中，它列出 git 已跟踪的文件和将会跟踪的文件，因此 `.gitignore` 所列的内容（如 `node_modules`）不会出现。

## 搜索

资源管理器的**搜索**标签页，或 <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>F</kbd>（Windows 和 Linux 上为 <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>S</kbd>），会在文件视图所显示的文件所在的主机上，搜索这些文件的文本。停止输入后就会搜索，不区分大小写；文件有变化时，按 <kbd>Return</kbd>（<kbd>Enter</kbd>）可重新搜索。输入框旁的按钮依次是 **区分大小写**、**全字匹配** 和 **使用正则表达式**，正则表达式采用 Go 的写法。

找到的行列在各自文件的下方，找到的文本会高亮：点击文件可将其折叠，点击某一行，会在编辑器窗格中打开该文件并定位到那一行；如果已有编辑器窗格显示该文件，就在那个窗格中打开。右键点击文件或某一行，可以在编辑器或编辑器窗格中打开它；把它拖到某个窗格上，就会在那里打开并定位到那一行。git 忽略的文件、二进制文件和超过 2 MB 的文件不会被搜索，一次搜索最多显示前 2,000 行。

<a id="review"></a>

## 审查

资源管理器的**审查**标签页，或 <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>P</kbd>（Windows 和 Linux 上为 <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>K</kbd>），会列出你所在窗格的仓库在 GitHub 上打开的拉取请求。它通过仓库所在主机上的 [GitHub CLI](https://cli.github.com) 读取，因此那里需要安装 `gh` 并已登录。列表来自分支推送到的远程仓库，通常是 `origin`；列表上方的仓库名可以选择该仓库在 GitHub 上的其他远程。**打开的**、**我的** 和 **待我审查** 用来筛选列表，列表中显示每个拉取请求的分支、检查和审查状态。点击拉取请求会在资源管理器中显示它；旁边的箭头会在 GitHub 上打开它。**对话** 显示它的描述、每位审查者的审查状态（已批准、要求更改或等待审查）、它的检查（点击可展开列表），评论和审查，以及针对行和文件的评论串，回复显示在它所回复的评论下方并与之分隔；点击评论串的位置可在 **文件** 中查看。**文件** 显示它的改动（与其基础分支一起获取），每个文件的差异中，行内评论显示在对应行的下方，针对整个文件的评论显示在差异上方。之后行已变化的评论串只显示在对话中，并标为已过时。**解决对话** 会在 GitHub 上解决评论串，之后它折叠为一行。标签页旁的箭头可在你的评论和已发布的评论之间逐条跳转。当仓库的某个工作树检出了拉取请求的头部（例如审查用的工作树），可以右键点击文件打开它，或把它拖到窗格上；否则文件不在磁盘上，无法打开。

拉取请求上的**审查**会让智能体审查它。点击后，Kero 会获取拉取请求的分支，并在该分支的[专属工作树](#sessions-in-their-own-worktree)中的新会话里启动智能体；来自分叉的拉取请求会检出为 `pr-<编号>`。右键点击按钮或拉取请求，可以改为把审查发给你所在窗格的智能体，或在窗格所在文件夹的新会话中启动智能体。审查开始前会显示提示词供你编辑。智能体就绪后 Kero 会输入提示词；如果 90 秒后智能体仍未就绪，Kero 会复制提示词。

**审查设置…**（齿轮）为每个仓库设置智能体命令和提示词，因为不同仓库使用的技能和工具不同，例如 `/code-review high {ticket}`。提示词中的 `{number}`、`{url}`、`{title}`、`{branch}`、`{base}` 和 `{author}` 会换成拉取请求的值，`{ticket}` 会换成标题、描述或分支中的第一个问题键，例如 `PROJ-123`；如果都没有，审查会请你输入。命令默认为 `claude`。

<a id="draft-reviews"></a>

### 草稿审查

智能体从不发布到 GitHub。它的评论通过 [Kero 的技能](./agents.md)教它使用的 `kero pr comment` 进入 Kero 保存的草稿审查；Kero 会检查每条评论都在拉取请求差异的行上（这也是 GitHub 唯一接受评论的行），或在拉取请求改动的文件上。默认提示词让智能体先审查整个拉取请求，再把每条想留下的评论对照代码核实，然后才添加。

智能体添加的评论会立即显示在拉取请求的 **文件** 中，并标为 **智能体**。和改动视图一样，你可以编辑或删除任何一条，也可以从某一行的边栏，或用文件标题中的评论按钮针对整个文件，添加自己的评论。智能体评论上的闪光图标会把关于它的问题输入到智能体的窗格中，由你写完。拉取请求下方的栏里有审查的摘要（即 GitHub 上审查的正文）和结论：**评论**、**批准** 或 **要求更改**（自己的拉取请求只能评论）。**发布审查** 会先确认，然后把摘要和评论作为一次审查发布，因此作者只会收到一次通知。审查不需要评论：可以在栏中直接批准，或只留下摘要。审查列表会标出草稿中有评论或摘要、或其智能体仍在工作的拉取请求。栏菜单中的 **丢弃审查…** 会删除草稿。

<a id="pull-request-notifications"></a>

### 通知

Kero 每 5 分钟检查一次你的项目所在的 GitHub 仓库，并在有新的拉取请求请求你审查时通知你。设置 › 通用 › Git 中可以设置哪些拉取请求会通知你 `pr-notify`（请求你审查的、别人打开的所有新拉取请求，或者都不通知，此时也停止检查），以及检查间隔 `pr-poll-interval`。点击通知会在该项目的会话中显示这个拉取请求。Kero 会记住已经看到的拉取请求，所以重启后不会再次通知；对一个仓库的第一次检查只会记下当前打开的拉取请求。

<a id="new-pull-request"></a>

### 新建拉取请求

**新建拉取请求** 为你所在窗格的分支创建拉取请求。表单显示要合并到的分支，起初是推送目标仓库的默认分支；点击它可以选择其他分支或其他远程的仓库。默认分支排在最前，其后按最近改动排列，输入文字可以筛选。标题和描述下方列出拉取请求带来的提交及其改动的文件，点击文件可展开其差异。只有提交会包含在内：表单会显示有多少文件尚未提交，以及有多少提交还不在推送目标上。标题旁的闪光图标会撰写标题和描述，方式与 **撰写信息** 撰写提交信息相同，使用 `commit-message-command`。只有一个提交的分支会以该提交的主题作为标题。

**创建拉取请求** 会先推送推送目标上没有的提交，然后用 `gh` 创建拉取请求并打开它。旁边的箭头中有 **创建为草稿** 和 **在 GitHub 上显示**；后者会打开 GitHub 创建拉取请求的页面，标题和描述已填好，由你在那里完成。如果分支已有打开的拉取请求，表单会改为显示它的链接。

设置 › 通用 › Git 中有告诉智能体如何撰写提交信息和拉取请求的提示词：`commit-message-prompt` 和 `pr-message-prompt`。在你修改之前，它们显示 Kero 自己的提示词，**恢复默认** 可以恢复。

## 在命令行中查看

`kero diff` 以 `git diff` 的格式打印窗格的改动，包括未跟踪的文件：

```sh
kero diff                       # 此窗格未提交的改动
kero diff --turn                # 它的智能体在上一轮中改了什么
kero diff review --branch       # review 会话自默认分支以来的改动
kero diff src/auth              # 只看这些路径
```

`kero status --json` 和 `kero ls --json` 会在 `git` 字段中包含每个窗格的分支和改动。

`kero do` 可以显示面板中的视图，就像智能体向你展示它完成的工作一样。需要在 **设置 › 智能体** 中启用 **远程控制**：

```sh
kero do changes.show                 # 改动视图
kero do files.show                   # 文件视图
kero do files.show path=src/main.go  # 打开此文件或文件夹
kero do search.show query=TODO       # 搜索视图，并搜索 TODO
```

## 关闭此功能

设置 `git-status = false`，或在设置中关闭 **显示 Git 状态**，Kero 就不会再在你的仓库中运行 git。
