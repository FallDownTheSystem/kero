# 改动

当会话在 git 仓库中工作时，Kero 会显示它的分支和改动，让你在窗格旁审阅智能体的工作。

## 分支一览

每个窗格的标题会显示它所在的分支，以及自上次提交以来改动增加和删除的行数：`fix-login +40 −2`。进行中的合并或变基也会显示在这里。

在边栏中，如果会话所在的分支不是仓库的默认分支（比如智能体在自己的 worktree 中工作），会直接显示该分支的名称。将鼠标悬停在会话上，可以看到它的分支、相对上游领先或落后多少，以及改动了多少文件。

## 改动面板

点击窗格的分支或窗口右上角的资源管理器按钮，或按 <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>G</kbd>，即可在会话右侧打开资源管理器并显示改动。资源管理器按钮会打开上次显示的视图，资源管理器打开后它仍留在窗口角落，再点一次即可关闭。资源管理器标题栏中的**加宽资源管理器**按钮会让它占满窗格留出的全部空间，再点一次恢复。设置 `sessions-sidebar = right` 时，会话位于窗口右侧，资源管理器位于左侧，其按钮在左上角。它列出改动过的文件，以及每个文件增加和删除了多少，比较基准可以是以下之一：

- **上一轮**：会话中的智能体上一次开始工作的位置，这样你只会看到它最近一轮做了什么，而不包括之前的改动。Kero 会在智能体开始时为 worktree 拍一个快照，不会动你的暂存区和文件。
- **未提交**：上一次提交，包括未跟踪的文件。
- **分支**：当前分支从仓库默认分支分出的位置，与拉取请求中看到的一致。

每个文件下方紧跟着它的 diff，依次排列；智能体继续编辑时，diff 也会随之更新。滚动到较长的 diff 中时，文件名会固定在顶部。点击文件名可以折叠或展开它的 diff：二进制文件以及改动行数特别多的文件默认折叠。拖动面板边缘可以调整宽度。

面板较窄时 diff 以统一视图显示，足够宽时则并排显示。列表摘要右侧的按钮可以在两者之间切换，`diff-layout` 设置会记住你的选择。旁边的换行按钮会按面板宽度折行显示长行，与文件视图和编辑器窗格中一样。

### 审阅一轮改动

在 **上一轮** 中，将鼠标悬停在某处改动上，会出现两个按钮：

- **还原**：把旧的内容放回文件中。
- **保留**：将这处改动标记为已审阅，并隐藏它。

只有在会话中没有智能体正在工作时才能还原，这样就不会与智能体的编辑冲突；而且文件必须仍与 diff 所示一致。如果文件在此期间又有改动，则会重新显示。

## 暂存与提交

在 **未提交** 中，文件分为两部分列出：下一次提交会包含的 **已暂存的改动**，以及尚未包含的 **改动**。每个文件的按钮可以暂存、取消暂存或放弃它的改动；放弃会先询问：未跟踪的文件会被删除，已删除的文件会恢复。分组标题上的按钮对其中所有文件做同样的事。**暂存所有改动** 不包含冲突，因为暂存冲突就会把它标记为已解决。

要暂存文件的一部分，将鼠标悬停在 diff 中的某处改动上，点击 **暂存**（在已暂存的改动中为 **取消暂存**）；**放弃** 会把它的旧行放回文件。只处理一处改动中的某些行时，点击它们的行号，按住 Shift 点击可选择范围，改动的按钮会变为 **暂存 N 行**、**取消暂存 N 行** 和 **放弃 N 行**。像 Git LFS 这样在存储时由 git 过滤器改变的文件，只能整个暂存。

<a id="committing"></a>

在列表下方的框中写下提交信息，点击 **提交**，或按 <kbd>⌘</kbd> <kbd>↩</kbd>（<kbd>Ctrl</kbd> <kbd>Enter</kbd>）。框中闪光图标的 **撰写信息** 会根据已暂存的内容撰写信息：由窗格中智能体对话的分叉撰写，它知道为什么做了这些改动，原对话不会改变；没有对话时，新运行 Claude Code 或 Codex。设置 `commit-message-command` 可改用其他命令撰写，提示通过标准输入传入。提交旁的箭头中有 **提交并推送**、**修改上次提交**、**签署** 和 **跳过钩子**。

## 分支、同步与储藏

列表上方的栏显示工作树的分支。点击它可以切换分支：输入以筛选分支，或输入新分支的名称，然后按 <kbd>Return</kbd>（<kbd>Enter</kbd>）。其中分支的菜单可以切换到它、从它新建分支、在专属工作树的会话中打开它、重命名或删除它、把它合并到你的分支，或把你的分支变基到它上面。有未提交的改动时切换，会询问先储藏它们，还是带着它们一起切换。

旁边的同步按钮会先拉取分支落后的提交，再推送领先的提交；没有上游的分支则会发布。**⋯** 菜单中有其他操作：

- **获取**、**从所有远程获取** 和 **获取并清理**。
- **拉取**（按你的 git 配置），或以合并、变基、仅快进的方式拉取。
- **推送**、**强制推送**（仅当远程分支仍是上次获取时的样子才覆盖），以及 **连同标签推送**。推送只推送这个分支，推送到它的推送目标。
- **储藏所有改动**、**储藏已暂存的改动** 和 **带信息储藏…**。
- **新建分支…**、**撤销上次提交**（其改动保持暂存）和 **刷新**。

拉取、合并和变基会先储藏未提交的改动，结束后再放回；如果它们冲突，就留在储藏中。需要密码的获取、拉取或推送会失败，并提供 **在终端中运行**，在终端中运行同一条命令，让 git 可以询问密码。

当智能体在工作树中工作时，改变文件的操作（如拉取或放弃）会先询问：**完成后** 在智能体完成后运行，**现在** 立即运行。暂存、提交和获取不会询问。

## 历史

资源管理器的 **历史** 标签页，或 <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>Y</kbd>（Windows 和 Linux 上为 <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>Y</kbd>），以图的形式显示工作树的提交：**全部** 显示所有分支的提交，**分支** 显示该分支、它的上游和默认分支的提交。本地分支和远程分支分开显示，因此同一提交上的分支和它的远程分支都会显示。尚未推送的提交会有标记。**筛选** 可以按信息、作者或哈希查找提交；文件视图中文件的菜单可以显示该文件的历史。

点击提交可查看它的文件，点击文件可查看它的 diff。未提交的改动显示在最上方，下面是储藏，可以应用、弹出或丢弃。提交的菜单：

- **复制哈希** 和 **复制分支名称**。
- **检出**：检出该提交上的分支；没有分支时，以分离状态检出提交本身。
- **在这里新建分支…** 和 **从这里在工作树中新建会话…**。
- **把 … 合并到 …**（也可用合并提交），以及 **把 … 变基到 …**。
- **拣选**、**还原提交**，以及 **重置到这里**：软重置保留之后的改动并保持暂存，混合重置保留但不暂存，硬重置则放弃它们。

## 冲突

合并、变基、拣选或还原因冲突而停止时，栏中和提交框上方会显示出来，每个冲突的文件都列在 **改动** 中。在编辑器或终端中解决文件后点击 **标记为已解决**，或从文件的菜单中选用一方的版本：以分支命名，如 **使用 main 的版本** 或 **使用 feature 的版本**；对文件所做的编辑会丢失，所以会先询问。文件菜单中或提交框上方的 **让智能体解决** 会请工作树中的智能体解决这些冲突并暂存，提交留给你来做。

没有冲突后，**继续** 会继续变基、拣选或还原，**提交合并** 会用 git 准备好的信息提交合并。**中止** 会在询问后放弃该操作，回到开始前的状态。

## 在专属工作树中运行的会话

多个智能体在同一个检出目录里并行工作，会被彼此的改动绊住。**会话 › 在工作树中新建会话…**（<kbd>⌘</kbd> <kbd>⌥</kbd> <kbd>T</kbd>）会询问分支名，然后在专属的 git 工作树中启动会话：一个从仓库默认分支创建并检出新分支的文件夹。

- 工作树位于仓库内的 `.kero/worktrees/<branch>`，Kero 通过 `.git/info/exclude`（而不是你的 `.gitignore`）忽略它。设置 `worktree-dir` 可以把工作树放到别处。
- 设置 `worktree-base = current`，可以从你所在的会话而不是默认分支创建分支。
- 会话会加入仓库所在的项目，边栏中会显示它的分支。

关闭会话时，Kero 会询问是否一并删除它的工作树：

- **没有未提交的改动：** 默认是“删除工作树”。分支若已合并会一并删除，否则会连同提交一起保留。
- **有未提交的改动：** Kero 会说明有多少文件会丢失，默认是“保留工作树”。
- **还有其他会话在这个工作树中工作：** 工作树会保留，Kero 不会询问。

在命令行中：

```sh
kero new --worktree fix-login -- claude   # 在专属工作树中、以新分支启动会话
kero new --worktree fix-login --base dev  # 从 dev 创建分支
kero close fix-login --remove-worktree    # 关闭会话并删除工作树
kero close fix-login --remove-worktree --force   # 即使有未提交的改动
```

## 文件

资源管理器的**文件**标签，或 <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>E</kbd>（Windows 和 Linux 上为 <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>E</kbd>），显示你所在窗格的工作树中的文件；不在仓库中时，显示它所在文件夹的文件。在远程主机上，显示的是该主机的文件。

点击文件夹，或按 <kbd>→</kbd> 和 <kbd>←</kbd>，展开或折叠它。点击文件，它会在树下方打开，按其语言高亮，并可直接编辑：<kbd>⌘</kbd> <kbd>S</kbd>（<kbd>Ctrl</kbd> <kbd>S</kbd>）保存，并保留原有的换行符。编辑过的文件在你查看其他文件时保持打开，并标为未保存。文件上方的换行按钮会按视图宽度折行显示长行。图片以图片显示；二进制文件和超过 4 MB 的文件不会打开。关闭 `files-preview` 后，点击只会选中文件，可从其菜单中的**预览**在树下方打开它。要把文件留在终端旁边，可在[编辑器窗格](./panes.md#editor-panes)中打开它。

树下方的 **新建文件…** 和 **新建文件夹…** 按钮可在所选文件夹中，或所选文件所在的文件夹中创建文件或文件夹。输入名称或类似 `src/util/new.go` 的路径，然后按 <kbd>Return</kbd>（<kbd>Enter</kbd>）创建；按 <kbd>Esc</kbd> 可取消。新文件会在树下方打开。其他按钮可刷新文件树或折叠其中的文件夹。文件夹菜单可在该文件夹中新建文件或文件夹，也可选择 **在此新建终端**，在此处打开终端。

按钮之间的 **筛选** 栏会在整个文件夹（包括已折叠的文件夹）中按名称查找文件和文件夹，并在它们所在的文件夹中显示。输入斜杠时改为按路径匹配，如 `src/main`。git 忽略的文件夹（如 `node_modules`）可按名称找到，但不会搜索其内容。按 <kbd>↓</kbd> 或 <kbd>Return</kbd>（<kbd>Enter</kbd>）转到找到的第一个文件，按 <kbd>Esc</kbd> 清除筛选，并在完整的树中显示所选文件。

保存只在文件仍是你打开时的样子时才写入。如果之后智能体或其他程序改动了它，Kero 会提示你，由你选择**重新载入**（放弃你的编辑）或**覆盖**。在你没有编辑时，它会跟随磁盘上的改动。

双击文件或右键点击它，可在编辑器中打开：即 `editor` 设置（如 `code` 或 `zed`），未设置时用系统打开该文件的应用。设置 `files-double-click = pane` 时，双击会在编辑器窗格中打开。除非关闭 `files-hidden`，否则会显示点文件。文件夹的菜单同样可在编辑器中打开文件夹（未设置时用系统打开文本文件的应用）。菜单中还可以在窗格中打开、用其他应用打开、在文件资源管理器或访达中显示，以及复制路径或相对于工作树的路径。

## 在命令行中查看

`kero diff` 以 `git diff` 的格式打印窗格的改动，包括未跟踪的文件：

```sh
kero diff                       # 此窗格未提交的改动
kero diff --turn                # 它的智能体在上一轮中改了什么
kero diff review --branch       # review 会话自默认分支以来的改动
kero diff src/auth              # 只看这些路径
```

`kero status --json` 和 `kero ls --json` 会在 `git` 字段中包含每个窗格的分支和改动。

`kero do` 可以显示面板中的视图，就像智能体向你展示它完成的工作一样。需要在 **设置 › 智能体** 中启用 **远程控制**：

```sh
kero do changes.show                 # 改动视图
kero do files.show                   # 文件视图
kero do files.show path=src/main.go  # 打开此文件或文件夹
```

## 关闭此功能

设置 `git-status = false`，或在设置中关闭 **显示 Git 状态**，Kero 就不会再在你的仓库中运行 git。
