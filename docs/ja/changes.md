# 変更

セッションが git リポジトリで作業していると、Kero はそのブランチと変更内容を表示し、エージェントの作業をペインの横でレビューできます。

## ブランチをひと目で

各ペインのタイトルには、作業中のブランチと、最後のコミットから追加・削除された行数が表示されます: `fix-login +40 −2`。進行中のマージやリベースもそこに表示されます。

サイドバーでは、リポジトリのデフォルト以外のブランチにいるセッション（専用のワークツリーで作業するエージェントなど）に、そのブランチ名が表示されます。セッションにポインタを合わせると、ブランチ、アップストリームとの差（先行・遅れ）、変更されたファイル数がわかります。

## 右サイドバー

ウィンドウの右のサイドバーには **ファイル**、**変更**、**履歴**、**レビュー** の 4 つのタブがあります。ウィンドウ右上のボタンか <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>B</kbd> で表示・非表示を切り替え、端をドラッグすると幅を変えられます（履歴のグラフ用にさらに広げられます）。非表示ボタンの横の**サイドバーを拡大**でペインを隠してその場所いっぱいに広げ、**すべてのペインを表示**で戻ります。ペインの横に置くには狭すぎるウィンドウでは自動で隠れ、ウィンドウを広げると戻ります。必要なときはボタンで表示できます。変更、ファイル、検索でクリックしたファイルと、レビューで開いたプルリクエストは、ペインの横のカード（ビューア）で開きます。ビューアは <kbd>×</kbd> で閉じ、<kbd>Esc</kbd> でペインに戻れます。ビューアの**ビューアを拡大**ボタンで、ペインの拡大と同じようにペインを隠してその場所いっぱいに広げ、**すべてのペインを表示**で戻ります。`sessions-sidebar = right` のときは、セッションがウインドウの右に、右サイドバーとビューアが左に置かれます。

## 変更

ペインのブランチをクリックするか、<kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>G</kbd> を押すと、変更タブが表示され、ペインの横に差分が開きます。次のいずれかの時点から変更されたファイルが、フォルダごとに、追加・削除行数とともに一覧されます:

- **直前のターン**: セッションのエージェントが最後に作業を始めた時点。最新のターンで何をしたかだけがわかり、それ以前の変更は含まれません。Kero はエージェントが作業を始めるときにワークツリーのスナップショットを取ります。インデックスやファイルには触れません。
- **未コミット**: 最後のコミット。未追跡のファイルも含みます。
- **ブランチ**: ブランチがリポジトリのデフォルトブランチから分かれた時点。プルリクエストと同じ見え方です。

タブでファイルをクリックすると、そのファイルまでスクロールした差分が表示されます。各ファイルのすぐ下に差分が順に表示され、エージェントが編集を続けると差分も追従します。差分の一番上にあるファイルはタブで強調表示されます。長い差分をスクロールしている間も、ファイル名は上部に残ります。ファイル名をクリックすると差分を折りたたんだり展開したりできます: バイナリファイルと変更行がとても多いファイルは、最初から折りたたまれています。**すべて折りたたむ** で全部を折りたたみ、**すべて展開** で全部を展開します。ファイルを右クリックすると、エディタやエディタペインで開けます。ペインにドラッグすると、そこで開きます。ペインと差分の間をドラッグすると幅を変えられます。

カードが狭い間は差分が統合表示され、広くなると左右に並べて表示されます。差分の上部にあるボタンで 2 つを切り替えられ、その選択は `diff-layout` 設定に保存されます。その隣の折り返しボタンで、ファイルやエディタペインと同じく、長い行をカードの幅で折り返します。タブでは、別のフォルダだけを含むフォルダは `src/app` のように 1 行にまとまり、クリックでフォルダを折りたたみます。未コミットでは、セクションのボタンがそのすべてのファイルにするように、フォルダのボタンでその中のファイルをステージ、ステージ解除、破棄できます。

### ターンをレビューする

**直前のターン**では、変更にポインタを合わせると 2 つのボタンが現れます:

- **元に戻す** は、ファイルに古い行を戻します。
- **保持** は、変更を確認済みにして隠します。

元に戻すは、セッションでエージェントが作業していない間だけ、そして差分の表示どおりのままのファイルにだけ使えます。エージェントの編集と競合しないためです。その間に変更されたファイルは、新しい差分として表示し直されます。

**ブランチ**では、変更には **元に戻す** だけがあります。ブランチが始まった時点の行をファイルに戻し、まだコミットしていない変更として残ります。

### レビューコメント

プルリクエストと同じように、エージェントの変更にコメントを付け、すべてのコメントをまとめてエージェントに送ります。**直前のターン**、**未コミット**、**ブランチ**では:

- 行番号にポインタを合わせて現れる **+** をクリックすると、その行にコメントできます。先に行番号をクリックし、Shift クリックで範囲を選んでおくと、選んだ行すべてにコメントできます。
- または、変更にポインタを合わせて **コメント** をクリックすると、その変更の選択した行に、選択がなければ変更全体にコメントできます。統合表示の差分で削除された行にコメントするには、この方法を使います。

行の下のボックスにコメントを書き、**コメント** をクリックするか、<kbd>⌘</kbd> <kbd>↩</kbd>（<kbd>Ctrl</kbd> <kbd>Enter</kbd>）を押します。<kbd>Esc</kbd> を押すと、コメントを書くのをやめます。コメントはその行の下に残り、編集や削除ができます。

ファイルの上のバーが、ワークツリーのコメントの数を示し、一覧します。コメントをクリックすると、そのファイルを該当の行で開きます。**エージェントに送る** は、ワークツリーで作業するエージェントのペインにコメントを 1 つのプロンプトとして貼り付け、送信します。各コメントには、ファイル、行番号、その行のテキストが付くので、行が移動した後でもエージェントは見つけられます。送ったコメントは、そのあと消えます。**プロンプトとしてコピー** は、代わりに同じプロンプトをコピーするので、別のエージェントに渡せます。**×**（**コメントを破棄**）は、それらを破棄します。コメントは Kero を終了するまで残ります。

## ステージとコミット

**未コミット**では、ファイルが 2 つのセクションに分かれて一覧されます。次のコミットにまだ入らない **変更** と、その下の、次のコミットに入る **ステージした変更** です。ステージしたファイルはすぐに移り、次のファイルがその場所に上がってきます。各ファイルのボタンで、ステージ、ステージの解除、変更の破棄ができます。破棄は先に確認します: 未追跡のファイルは削除され、削除したファイルは元に戻ります。セクションのタイトルのボタンは、そのすべてのファイルに同じことをします。**すべての変更をステージ** は競合を含めません。競合をステージすると解決済みになるためです。

ファイルを右クリックして **.gitignore に追加**、またはツリーのフォルダを右クリックして **フォルダを .gitignore に追加** を選ぶと、ワークツリーの最上位の `.gitignore` に追加されます。Git は、すでに追跡しているファイルを `.gitignore` に書いても追跡し続けます。そのため、追跡されているファイルや、追跡されているファイルを含むフォルダでは、追跡もやめるかどうかを Kero が確認します。追跡をやめたファイルは次のコミットでリポジトリから削除され、ディスクには残ります。

ファイルの一部をステージするには、差分の変更にポインタを合わせて **ステージ**（ステージした変更では **ステージを解除**）をクリックします。変更の **破棄** は、その古い行をファイルに戻します。変更の一部の行だけを扱うには、行番号をクリックし、Shift クリックで範囲を選びます。変更のボタンが **N 行をステージ**、**N 行のステージを解除**、**N 行を破棄** に変わります。Git LFS のように、保存するときに git のフィルタが変えるファイルは、ファイルごとにステージします。

<a id="committing"></a>

一覧の下のボックスにメッセージを書き、**コミット** をクリックするか、<kbd>⌘</kbd> <kbd>↩</kbd>（<kbd>Ctrl</kbd> <kbd>Enter</kbd>）を押します。ボックスのきらめきの **メッセージを書く** は、ステージした内容からメッセージを書かせます。書くのは、ペインのエージェントの会話のフォークです。変更した理由を知っていて、元の会話は変わりません。会話がなければ Claude Code か Codex を新しく実行します。`commit-message-command` を設定すると、別のコマンドで書きます。コマンドはシェルで実行され、プロンプトは標準入力で渡されます。中の `{session}` はペインのエージェントの会話の ID になるので、自分の起動コマンドでフォークできます: `cc -p --resume {session} --fork-session`。コミットの隣の矢印には、**コミットしてプッシュ**、**最後のコミットを修正**、**サインオフ**、**フックを飛ばす** があります。

## ブランチ、同期、スタッシュ

一覧の上のバーに、ワークツリーのブランチが表示されます。クリックするとブランチの切り替えが開きます。**ワークツリー**、フォルダごとの**ブランチ**、**リモート**、**タグ**、**スタッシュ**のグループは折りたためます。上のフィルタはどのグループからでも探せ、新しいブランチの名前にもなります。項目をクリックすると、切り替えを開いたまま、そのコミットを履歴のグラフで選択して表示します。ブランチをダブルクリックするか <kbd>Return</kbd>（<kbd>Enter</kbd>）を押すとチェックアウトし、ワークツリーをダブルクリックするとそのセッションを開きます。**設定 › Git › 古いブランチを隠す**を使うと、その週数コミットのないブランチは、フィルタで見つけない限り **… を表示** の後ろに隠れます。そこでのブランチのメニューでは、切り替え、そこからのブランチ作成、専用のワークツリーのセッションで開く、名前の変更、削除、今のブランチへのマージ、今のブランチのリベースができます。コミットしていない変更があるまま切り替えると、先にスタッシュするか、持っていくかを尋ねます。

その隣の同期ボタンは、ブランチが遅れている分をプルしてから、進んでいる分をプッシュします。アップストリームのないブランチは公開します。**⋯** メニューにはほかの操作があります:

- **フェッチ**、**すべてのリモートからフェッチ**、**フェッチして削除済みを整理**。
- **プル**（git の設定どおり）、またはマージ、リベース、早送りのみのプル。
- **プッシュ**、**強制プッシュ**（リモートのブランチが最後にフェッチしたときのままの場合だけ上書きします）、**タグと一緒にプッシュ**。プッシュはそのブランチだけを、プッシュ先に送ります。
- **すべての変更をスタッシュ**、**ステージした変更をスタッシュ**、**メッセージを付けてスタッシュ…**。
- **新規ブランチ…**、**最後のコミットを取り消す**（変更はステージしたまま残ります）、**更新**。

一部のファイルだけをスタッシュして残りの作業を続けるには、変更タブでファイル、フォルダ、セクションの **スタッシュに追加** ボタンをクリックします。ファイルはほかのセクションの下の **スタッシュする変更** セクションに移ります。必要ならスタッシュに名前を付け、**N 個のファイルをスタッシュ** をクリックすると、ステージ済みかどうかや未追跡かにかかわらず、それらの変更が 1 つのスタッシュに入り、ほかのファイルはそのまま残ります。

プル、マージ、リベースは、コミットしていない変更を先にスタッシュし、終わると戻します。変更が競合したときは、スタッシュに残ります。パスワードが必要なフェッチ、プル、プッシュは **ターミナルで実行** とともに失敗します。同じコマンドをターミナルで実行し、git がパスワードを尋ねられるようにします。

エージェントがワークツリーで作業している間にファイルを変える操作（プルや破棄など）は、先に確認します。**終わってから** はエージェントが終わってから、**今すぐ** はすぐに実行します。ステージ、コミット、フェッチは確認しません。

## 履歴

右サイドバーの **履歴** タブ、または <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>Y</kbd>（Windows と Linux では <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>Y</kbd>）で、ワークツリーのコミットをグラフで表示します。**すべて** ではすべてのブランチのコミットを、**ブランチ** ではそのブランチとアップストリーム、デフォルトブランチのコミットを表示します。ローカルのブランチとリモートのブランチは分けて表示されるので、同じコミットにあるブランチとリモートのブランチは両方見えます。まだプッシュしていないコミットには印が付きます。**フィルタ** でメッセージ、作成者、ハッシュからコミットを探せます。ファイルタブのファイルのメニューからは、そのファイルの履歴を表示できます。

スタッシュの下の **ワークツリー** セクションは、リポジトリのワークツリーを、削除したときに失われるものとともに一覧します。変更したファイルやどのリモートにもないコミットはオレンジで、何も失われないときは緑で *マージ済み* か *プッシュ済み* と表示されます。**プッシュ** はワークツリーのブランチをプッシュし、**セッションで開く** はそこで作業しているセッションを表示するか、新しく始めます。**ワークツリーを削除** は先に確認します。変更のあるワークツリーは **それでも削除** を選んだときだけ削除され、未プッシュのコミットがあるものはブランチを残し、何も失われないものは **ブランチごと削除** できます。セッションのために作られたワークツリーは、そのセッションとともに閉じます。メニューではパスのコピーや、そのブランチを今のブランチへマージでき、**見つからないワークツリーを整理** はフォルダが削除されたものを忘れます。**+** で新しいワークツリーでセッションを始め、コミットのメニューの **… を新しいワークツリーで開く** でそのブランチを開けます。

コミットのブランチ、タグ、スタッシュは、その線の色でコミットの横に表示され、種類ごとにアイコンが付きます: ブランチ、リモートのブランチ（地球儀）、別のワークツリーでチェックアウトされたブランチ（フォルダ）、タグ、スタッシュ。今いるブランチは太字で、枠線が付きます。スタッシュのメニューで適用、取り出し、破棄ができ、ブランチが別のワークツリーでチェックアウトされているコミットのメニューには、チェックアウトの代わりに**ワークツリーを開く**があります。コミットをクリックするとファイルがフォルダごとに表示され、ファイルをクリックするとそのコミットの差分がビューアでそのファイルの位置に開きます。ビューアをスクロールすると、一番上のファイルが一覧で選択されて表示されます。ファイルのメニューでは、変更パネルと同じようにファイルを開けるほか、**ファイルの履歴を表示**でその履歴を表示できます。コミットしていない変更が一番上に、その下にスタッシュが表示され、適用、取り出し、破棄ができます。コミットのメニュー:

- **ハッシュをコピー**、**ブランチ名をコピー**。
- **チェックアウト**: そのコミットにあるブランチを、ブランチがなければコミット自体をデタッチしてチェックアウトします。リモートのブランチは同じ名前の手元のブランチとしてチェックアウトされ、手元が遅れていれば先にリモートに追いつかせます。双方に相手にないコミットがあるときは、手元のブランチに切り替えてプルしてください。
- **ここで新規ブランチ…**、**ここからワークツリーで新規セッション…**。
- **… を … にマージ**（マージコミットでも）、**… を … にリベース**、**… を … にインタラクティブリベース**。
- **チェリーピック**、**コミットをリバート**、**ここにリセット**: ソフトは以降の変更をステージしたまま、ミックスはステージせずに残し、ハードは破棄します。

### インタラクティブリベース

コミットやブランチのメニューの **… を … にインタラクティブリベース** は、そのコミット以降にブランチにあるコミットを、新しいものを上にして一覧します。それぞれの扱いをメニューかキーで決めます: <kbd>P</kbd> **Pick** はそのまま残し、<kbd>R</kbd> **Reword** は新しいメッセージにし、<kbd>E</kbd> **Edit** はそこで止まって変更でき、<kbd>S</kbd> **Squash** と <kbd>F</kbd> **Fixup** は下のコミットとまとめて、両方のメッセージか下のメッセージだけを残し、<kbd>D</kbd> **Drop** は取り除きます。コミットをドラッグするか、<kbd>Alt</kbd> <kbd>↑</kbd> と <kbd>Alt</kbd> <kbd>↓</kbd> で動かします。Reword にしたコミットの下には、新しい件名と説明を書くパネルが開きます。一覧の下の **コミット** と **変更** は、選んだコミットのメッセージとファイルです。

**現在の状態を一時ブランチにバックアップする** は、先に今の位置にブランチを作り、戻れるようにします。**リベース** は、ほかのリベースと同じくコミットしていない変更をスタッシュし、一覧どおりにコミットを適用し直します。Edit のコミットや競合で止まったら、**続行** で続けます。マージコミットを含む範囲は平らになってしまうので、この方法ではリベースできません。

## 競合

マージ、リベース、チェリーピック、リバートが競合で止まると、バーとコミットボックスの上にそう表示され、競合したファイルが **変更** に一覧されます。ファイルをエディタやターミナルで解決して **解決済みにする** をクリックするか、ファイルのメニューから片方の版を選びます: ブランチの名前で **main の版を使う** や **feature の版を使う** と表示されます。ファイルに加えた編集は失われるので、先に確認します。同じメニューの **マージエディタで開く** は、ファイルをエディタペインでマージエディタとして開きます: 上に 2 つの版が競合ごとにそろって並び、下にファイルがあり、編集できます。競合の上の **main の行を使う** や **feature の行を使う** にチェックすると、その版の行がファイルに入ります。両方にチェックすると、チェックした順に両方入ります。ペインのヘッダーは残りの競合を数えて競合の間を移動し、そのメニューはすべての競合で片方の版の行を使うか、ファイルをテキストで表示します。競合がなくなると、**保存して解決済みにする** がファイルを保存してステージします。競合中のファイルは、解決済みにするまで、どのエディタペインでもこの形で開きます。ファイルのメニュー、またはコミットボックスの上の **エージェントで解決** は、ワークツリーで作業するエージェントに、すべての競合を解決してステージするよう頼みます。コミットはあなたに任されます。

競合がなくなると、**続行** でリベース、チェリーピック、リバートを続け、**マージをコミット** で git が用意したメッセージでマージをコミットします。**中止** は確認してから操作をやめ、始める前の状態に戻します。

## 専用のワークツリーで動くセッション

1 つのチェックアウトで並んで作業するエージェントは、互いの変更につまずきます。**セッション › ワークツリーで新規セッション…**（<kbd>⌘</kbd> <kbd>⌥</kbd> <kbd>T</kbd>）は**ワークツリーで**を有効にした[新規セッションのダイアログ](./sessions.md#new-session-dialog)を開き、専用の git ワークツリーでセッションを開始します: 選んだブランチ、または名前を付けてリポジトリのデフォルトブランチから作った新しいブランチをチェックアウトするフォルダです。サイドバーのプロジェクトのメニューにもあり、そのプロジェクトのリポジトリのセッションを開始します。メニューバーのない Windows と Linux では、メニューバーのメニューは設定の隣にあるサイドバーの**メニュー**ボタン（⋯）にあります。

- ワークツリーはリポジトリ内の `.kero/worktrees/<branch>` に置かれます。Kero はそれを `.gitignore` ではなく `.git/info/exclude` で無視します。ほかの場所に置くには `worktree-dir` を設定します。
- ワークツリーを作る前に、Kero は元のブランチを取得してリモートのブランチから作るので、ローカルの `main` が古くても問題ありません。オフラインのときや、ローカルのブランチにリモートにないコミットがあるときは、ローカルのブランチから作ります。常にローカルのブランチから作るには `worktree-from-origin = false` を設定します。
- 新しいブランチをデフォルトブランチではなくプロジェクトのフォルダのブランチから作るには `worktree-base = current` を設定します。
- 新しいワークツリーには git が追跡するファイルしかありません。`.claude/settings.local.json`、`CLAUDE.local.md`、`.env` のような無視されたファイルも持っていくには、Claude Code のワークツリーと同じく、リポジトリの最上位の `.worktreeinclude` に `.gitignore` の書式で並べます。Kero は一致する無視されたファイルをコピーします。ワークツリーにすでにあるファイルはそのままです。`node_modules` とほかのワークツリーは飛ばし、丸ごと無視されたフォルダには、`cache/keep.txt` のようにその中のパスを指すパターンがあるときだけ入ります。
- セッションはリポジトリのプロジェクトに入り、サイドバーにはそのブランチが表示されます。

セッションを閉じると、ワークツリーも削除するか尋ねます:

- **未コミットの変更がない:** 既定は「ワークツリーを削除」です。ブランチはマージ済みなら一緒に削除され、そうでなければコミットとともに残ります。
- **未コミットの変更がある:** Kero は失われるファイルの数を示し、既定は「ワークツリーを残す」です。
- **ほかのセッションがそのワークツリーで作業している:** ワークツリーは残り、Kero は尋ねません。

コマンドラインから:

```sh
kero new --worktree fix-login -- claude   # 専用のワークツリーで、新しいブランチのセッション
kero new --worktree fix-login --base dev  # dev から分岐する
kero close fix-login --remove-worktree    # 閉じて、ワークツリーを削除する
kero close fix-login --remove-worktree --force   # 未コミットの変更があっても
```

## ファイル

右サイドバーの**ファイル**タブ、または <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>E</kbd>（Windows と Linux では <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>E</kbd>）で、今いるペインのワークツリー、リポジトリの外ならそのフォルダのファイルを表示します。リモートホストでは、そのホストのファイルです。git が無視するものは薄く表示され、`.git` は表示されません。ドットファイルは `files-hidden` をオフにしない限り表示されます。

フォルダをクリックすると展開し、ファイルをクリックするとペインの横のビューアで開きます。キーでも移動できます：<kbd>↑</kbd> と <kbd>↓</kbd> で移動し、<kbd>→</kbd> と <kbd>←</kbd> でフォルダを開閉し、<kbd>Return</kbd>（<kbd>Enter</kbd>）でファイルを開き、<kbd>⌘</kbd> <kbd>↩</kbd>（<kbd>Ctrl</kbd> <kbd>Enter</kbd>）でエディタペインに開きます。ファイルはビューアに言語に合わせてハイライトされて開き、検索（<kbd>⌘</kbd> <kbd>F</kbd>）や編集ができます。読んでいる間もファイルの変更に追従します。ビューアに表示するファイルは一度に 1 つで、別のファイルを開くときは先に変更を保存するか確認されます。ボタンで文字を小さく・大きくしたり、長い行を折り返したりでき、Markdown ファイルでは **Markdown をプレビュー** で表示どおりに見られます。画像は画像として表示され、バイナリファイルと 4 MB を超えるファイルは開きません。**エディタで開く** でエディタに、**ペインで開く** で[エディタペイン](./panes.md#editor-panes)に開き、ターミナルの隣に置いておけます。

ツリーの上のボタンで、最上位に新しいファイルやフォルダを作ったり、ファイルのテキストを検索したり、ツリーを更新したり、フォルダを折りたたんだりできます。ファイルやフォルダのメニュー（右クリック）では、そのフォルダに作成したり、名前を変更したり、削除したりできます。表示される場所に名前を入力して <kbd>Return</kbd>（<kbd>Enter</kbd>）を押します。`docs/notes.md` のような名前は途中のフォルダも作り、新しいファイルはビューアで開きます。削除は先に確認され、ゴミ箱に移されます。移せるゴミ箱のないリモートホストでは、完全に削除されます。

その下の **フィルタ** 欄は、閉じたフォルダも含めてフォルダ全体からファイルとフォルダを名前で探し、それらを含むフォルダの中に表示します。スラッシュを入力すると、`src/main` のようにパスで探します。`node_modules` など git が無視するフォルダは、名前では見つかりますが、中は検索しません。<kbd>↓</kbd> か <kbd>Return</kbd>（<kbd>Enter</kbd>）で最初に見つかったファイルを開き、<kbd>Esc</kbd> でフィルタを消去します。

ファイルのメニューからは、専用のエディタペインで開いたり、履歴を表示したりもできます。フォルダのメニューからは、そこでターミナルを開けます。どちらも、エディタで開く、Windows ではほかのアプリで開く、エクスプローラーや Finder で表示する、パスやワークツリーからの相対パスをコピーすることができます。ファイルをペインにドラッグすると、その横か、エディタペインの代わりにエディタペインで開きます。エディタは `editor` 設定（`code` や `zed` など）、未設定ならシステムがそのファイルを開くアプリです。

<a id="editing"></a>

### 編集

ファイルタブから開いたファイル、エディタペインのファイル、変更タブの差分の新しい側は、VS Code や Zed と同じように編集できます。<kbd>⌘</kbd> <kbd>S</kbd>（<kbd>Ctrl</kbd> <kbd>S</kbd>）で、改行コードを保ったまま今いるファイルを保存します。保存するまでは、ビューアの <kbd>×</kbd> と差分のファイル名の横に点が表示されます。ビューアを閉じるときや別のファイルを開くときは、先に変更を保存するか確認されます。Kero を終了するときは確認されず、次に開いたときに、保存していない変更がそのファイルとともに未保存のまま戻ります。

変更していないファイルは、ディスク上の変更に追従します。変更した後は自分の版が残り、その間にエージェントや別のプログラムがファイルを変更していた場合は、保存するときに上書きするか、変更を破棄して今のファイルを表示するかを確認されます。

### ファイルへ移動

**セッション › ファイルへ移動…**（<kbd>⌘</kbd> <kbd>⇧</kbd> <kbd>N</kbd>、Windows と Linux では <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>N</kbd>）は、今いるペインのワークツリーのファイルを、名前の文字を順に入力して探します: `usvc` で `user_service.go` が見つかります。名前の一致が先で、パスの一致はその後に並びます。スラッシュを入力すると、`src/main` のようにパスだけで探します。<kbd>Return</kbd>（<kbd>Enter</kbd>）で、ファイルタブでクリックしたときと同じようにビューアで開き、<kbd>⌘</kbd> <kbd>↩</kbd>（<kbd>Ctrl</kbd> <kbd>Enter</kbd>）では専用のエディタペインで開きます。リポジトリでは、git が追跡しているファイルと、これから追跡するファイルを一覧するので、`node_modules` など `.gitignore` に書かれたものは含まれません。

## 検索

ファイルタブの検索ボタン、または <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>F</kbd>（Windows と Linux では <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>S</kbd>）で、ファイルタブに表示されるファイルのテキストを、それらがあるホスト上で、右サイドバーで検索します。入力が止まると検索が始まり、大文字と小文字は区別しません。ファイルが変わったときは、<kbd>Return</kbd>（<kbd>Enter</kbd>）でもう一度検索します。欄の隣のボタンは、**大文字と小文字を区別**、**単語単位で検索**、**正規表現を使う** で、正規表現は Go の構文で書きます。

見つかった行は、そのファイルの下に一覧され、見つかったテキストがハイライトされます。ファイルをクリックすると折りたたみ、行をクリックすると、そのファイルをその行でエディタペインに開きます。すでにそのファイルを表示しているエディタペインがあれば、そこで開きます。ファイルや行を右クリックすると、エディタやエディタペインで開けます。ペインにドラッグすると、そこでその行に開きます。git が無視するファイル、バイナリファイル、2 MB を超えるファイルは検索されず、検索結果には最初の 2,000 行が表示されます。

## レビュー

右サイドバーの**レビュー**タブ、または <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>P</kbd>（Windows と Linux では <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>K</kbd>）は、今いるペインのリポジトリの GitHub 上のオープンなプルリクエストを一覧します。リポジトリがあるホストの [GitHub CLI](https://cli.github.com) で読むので、そこに `gh` をインストールしてサインインしておく必要があります。一覧はブランチのプッシュ先のリモート（たいていは `origin`）のものです。一覧の上のリポジトリ名で、GitHub 上の別のリモートを選べます。**オープン**、**自分の**、**レビュー待ち** で一覧を絞り込めます。各プルリクエストのブランチ、チェック、レビューが表示されます。プルリクエストをクリックすると、ペインの横のビューアに表示されます。隣の矢印は GitHub で開きます。**会話** には、説明、各レビュアーのレビューの状態 (承認、変更を要求、レビュー待ち)、チェック (クリックで一覧)、コメントとレビュー、そして行やファイルへのコメントのスレッドが表示されます。返信は、返信先のコメントの下に区切って表示されます。スレッドの場所をクリックすると **ファイル** で表示します。**ファイル** には、ベースと一緒に取得した変更が表示され、各ファイルの差分の行の下に、その行へのコメントが、差分の上にファイル全体へのコメントが表示されます。その後で行が変わったスレッドは、古いものとして会話にだけ表示されます。**会話を解決** は GitHub でスレッドを解決し、スレッドは一行に畳まれます。タブの隣の矢印で、自分のコメントと投稿済みのコメントを順に移動できます。リポジトリのワークツリーがプルリクエストのヘッドをチェックアウトしているとき (レビュー用のワークツリーなど) は、ファイルを右クリックして開くか、ペインにドラッグできます。そうでなければ、ファイルはディスクにないので開けません。

プルリクエストの**レビュー**は、エージェントにレビューさせます。クリックすると、プルリクエストのブランチを取得し、そのブランチの[専用のワークツリー](#sessions-in-their-own-worktree)の新しいセッションでエージェントを起動します。レビューごとに、プルリクエストを専用のブランチ `review/pr-<番号>`（次は `review/pr-<番号>-2`、…）にチェックアウトするので、同じプルリクエストを何度でもレビューでき、あなたのチェックアウトや別のワークツリーがそのブランチにあってもかまいません。変更タブからそのブランチをプッシュすると、プルリクエストのブランチに送られます。git では `git push origin HEAD:<ブランチ>` を実行します。ワークツリーごとレビューを閉じると、プルリクエストのブランチにコミットがあれば、そのブランチも削除します。ボタンかプルリクエストを右クリックすると、今いるペインのエージェントに送るか、ペインのフォルダの新しいセッションでエージェントを起動するかを選べます。レビューが始まる前にプロンプトが表示され、編集できます。新しいセッションのエージェントにはプロンプトをコマンドの引数として渡すので、何も入力されることなくすぐにレビューを始めます。今いるペインのエージェントにはプロンプトを貼り付けます。
プルリクエストをレビューするセッションは、サイドバーで**レビュー**と表示され、プルリクエストの上の**レビューエージェント**に、サイドバーと同じ状態とエージェントの最後のメッセージとともに一覧されます。クリックするとそのセッションに移動します。メニューからプルリクエストを表示したり、セッションを閉じたりできます（ワークツリーも削除するか確認します）。レビューエージェントのあるプルリクエストには、行とページで**レビュー**の代わりに**エージェント**が表示され、エージェントに移動します。セッションを閉じてもワークツリーを残したレビューは一覧に残り、そのワークツリーで再レビューするか、削除できます。**ワークツリーを削除…**は先に確認し、失われる変更ファイルの数を示します。すでにレビューのあるプルリクエストをレビューすると、そのエージェントを開くか、新しいワークツリーではなくそのワークツリーでレビューするかを選べます。

**リポジトリの設定…**（歯車）では、リポジトリごとにエージェントのコマンドとレビューのプロンプトを設定します。リポジトリによって使うスキルやツールが違うからです（`/code-review high {ticket}` など）。プロンプトの `{number}`、`{url}`、`{title}`、`{branch}`、`{base}`、`{author}` はプルリクエストの値になり、`{ticket}` はタイトル、説明、ブランチにある最初の課題キー（`PROJ-123` など）になります。どこにもなければ、レビューが入力を求めます。コマンドは、設定しなければ `claude` です。Kero はプロンプトを 1 つの引数としてコマンドの後に渡します（Claude Code や Codex は最初のプロンプトをこう受け取ります）。別の位置で受け取るコマンドなら、`codex exec {prompt} --full-auto` のように `{prompt}` を置きます。コマンドでもプルリクエストのプレースホルダーが使えます。

プルリクエストのページでは、タイトルの下に、そのままマージできるか、できないならその理由（競合、必須のレビューやチェック、ベースより遅れたブランチ、ドラフト）が表示されます。ボタンは、マージ、ドラフトのレビュー可能化、クローズしたものの再オープン、マージ済みのもののブランチ削除またはリバートを行います。隣の **⋯** には残りの操作があります：**マージ…**、**自動マージを有効にする…** または **自動マージを無効にする**、**ブランチを更新**（リベースでも）、**ドラフトに戻す**、**プルリクエストをクローズ…**、**リバート…**、**ブランチを削除…**。**マージ** は、リポジトリが許す方法（スカッシュ、マージコミット、リベース）のどれでマージするか、マージ後にブランチを削除するかを尋ねます。見ていたコミットでのみマージするので、その後に push があれば止まります。条件を満たしていない間は、**自動マージを有効にする** で条件を満たしたときに GitHub がマージします。メンテナーの承認を待つワークフロー実行があるフォークのプルリクエストには **承認** があり、フォークのコードを実行するので先に確認を求めます。どの操作もあなたとして `gh` を使うので、できることは GitHub が決め、ページはそれだけを表示します。一覧のプルリクエストを右クリックすると、マージ、ブランチを更新、レビュー可能にする／ドラフトに戻す、クローズができます。**リポジトリの設定…** では、**マージ** の初期値となるリポジトリの既定のマージ方法 `repo-merge-method` を設定できます。別の方法でマージするときに **このリポジトリの既定にする** をチェックしても設定されます。設定がなければ、スカッシュ、マージコミット、リベースのうちリポジトリが許す最初のものです。

<a id="draft-reviews"></a>

### 下書きのレビュー

エージェントは GitHub に投稿しません。コメントは、[Kero のスキル](./agents.md)が教える `kero pr comment` で、Kero が保持する下書きのレビューに入ります。Kero は、各コメントがプルリクエストの差分の行 (GitHub がコメントを受け付ける唯一の行)、またはプルリクエストが変更するファイルにあることを確認します。デフォルトのプロンプトでは、エージェントはまずプルリクエスト全体をレビューし、それからコメントを一つずつコードと照らし合わせて確認してから追加します。

コメントは、エージェントが追加するとすぐにプルリクエストの **ファイル** に **エージェント** の印付きで表示されます。変更タブと同じように、どれでも編集・削除でき、行のガターから、またはヘッダーのコメントボタンでファイル全体に、自分のコメントも追加できます。エージェントのコメントのきらめきは、それについての質問をエージェントのペインに入力し、続きはあなたが書きます。プルリクエストの下のバーには、レビューの概要 (GitHub でのレビューの本文) と判定 (**コメント**、**承認**、**変更を要求**。自分のプルリクエストではコメントだけ) があります。**レビューを投稿** は確認してから、概要とコメントを 1 つのレビューとして投稿するので、作成者への通知は 1 回です。コメントがなくてもレビューできます。バーから承認したり、概要だけを残したりできます。レビューの一覧では、コメントか概要のある下書き、またはエージェントが作業中の下書きがあるプルリクエストに印が付きます。バーの **下書きを開始** は、エージェントなしで下書きを始めます。自分のエージェントが `kero pr comment --pr <番号>` でコメントを追加できます。バーのメニューの **レビューを破棄…** は下書きを削除します。

<a id="pull-request-notifications"></a>

### 通知

Kero は 5 分ごとにプロジェクトの GitHub リポジトリを確認し、あなたにレビューを依頼する新しいプルリクエストを通知します。設定 › Git では、通知するプルリクエスト `pr-notify` (レビュー依頼、他の人が開いた新しいものすべて、またはなし。なしでは確認も止まります) と、確認する間隔 `pr-poll-interval` を設定します。通知をクリックすると、そのプロジェクトのセッションでプルリクエストが表示されます。Kero は確認したものを覚えているので、再起動しても再び通知しません。リポジトリの最初の確認は、開いているものを覚えるだけです。

### 新しいプルリクエスト

**新しいプルリクエスト**は、今いるペインのブランチのプルリクエストを作ります。フォームにはマージ先のブランチが表示されます。最初はプッシュ先のリポジトリのデフォルトブランチです。クリックすると、別のブランチや別のリモートのリポジトリを選べます。デフォルトブランチが先頭で、その後は最近変更されたものから並び、入力すると絞り込めます。タイトルと説明の下には、プルリクエストに入るコミットと、それらが変更するファイルが一覧されます。ファイルをクリックすると差分が開きます。入るのはコミットだけです。フォームには、コミットしていないファイルの数と、プッシュ先にまだないコミットの数が表示されます。タイトルの隣のきらめきは、**メッセージを書く** がコミットメッセージを書くのと同じように、`commit-message-command` でタイトルと説明を書かせます。コミットが一つだけのブランチは、その件名をタイトルにします。

**プルリクエストを作成** は、プッシュ先にないコミットをプッシュしてから、`gh` でプルリクエストを作成して開きます。隣の矢印には **ドラフトとして作成** と **GitHub で表示** があります。**GitHub で表示** は、タイトルと説明を入力した状態で GitHub のプルリクエスト作成ページを開き、そこで仕上げられます。ブランチにすでにオープンなプルリクエストがあれば、フォームはそのリンクを表示します。

設定 › Git には、エージェントがコミットメッセージとプルリクエストを書く方法を指示するプロンプト `commit-message-prompt` と `pr-message-prompt` があります。変更するまでは Kero のものが表示され、**デフォルトに戻す** で戻せます。そこにあるレビューのプロンプト `pr-review-prompt` は、レビューするエージェントへの指示です。レビュータブの **リポジトリの設定…** で、この 3 つをリポジトリごとに置き換えられます。変更しないプロンプトは設定のものに従います。

## コマンドラインから

`kero diff` は、ペインの変更を `git diff` と同じ形式で、未追跡のファイルも含めて出力します:

```sh
kero diff                       # このペインの未コミットの変更
kero diff --turn                # エージェントが直前のターンで変更したもの
kero diff review --branch       # review セッションのデフォルトブランチ以降の変更
kero diff src/auth              # これらのパスだけ
```

`kero status --json` と `kero ls --json` には、各ペインのブランチと変更が `git` として含まれます。

`kero do` では、エージェントが作業内容を表示するように、右サイドバーのタブを表示できます。**設定 › エージェント** の **リモート操作** が必要です:

```sh
kero do changes.show                 # 変更タブ
kero do files.show                   # ファイルタブ
kero do files.show path=src/main.go  # このファイルをビューアに、またはこのフォルダを開いた状態
kero do search.show query=TODO       # 検索で TODO を検索した状態
```

## オフにする

`git-status = false` を設定するか、設定で **git の状態を表示** をオフにすると、Kero はリポジトリで git を実行しなくなります。
