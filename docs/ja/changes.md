# 変更

セッションが git リポジトリで作業していると、Kero はそのブランチと変更内容を表示し、エージェントの作業をペインの横でレビューできます。

## ブランチをひと目で

各ペインのタイトルには、作業中のブランチと、最後のコミットから追加・削除された行数が表示されます: `fix-login +40 −2`。進行中のマージやリベースもそこに表示されます。

サイドバーでは、リポジトリのデフォルト以外のブランチにいるセッション（専用のワークツリーで作業するエージェントなど）に、そのブランチ名が表示されます。セッションにポインタを合わせると、ブランチ、アップストリームとの差（先行・遅れ）、変更されたファイル数がわかります。

## 変更パネル

ペインのブランチかウインドウ右上のエクスプローラーボタンをクリックするか、<kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>G</kbd> を押すと、セッションの右にエクスプローラーが開き、変更を示します。エクスプローラーボタンは最後に表示したビューを開き、エクスプローラーが開いてもウインドウの角に残るので、同じボタンで閉じられます。エクスプローラーのヘッダーの**エクスプローラーを広げる**ボタンで、もう一度押すまでペインが空ける幅いっぱいに広げます。`sessions-sidebar = right` のときは、セッションがウインドウの右に、エクスプローラーが左に置かれ、そのボタンは左上に来ます。次のいずれかの時点から変更されたファイルが、それぞれの追加・削除行数とともに一覧されます:

- **直前のターン**: セッションのエージェントが最後に作業を始めた時点。最新のターンで何をしたかだけがわかり、それ以前の変更は含まれません。Kero はエージェントが作業を始めるときにワークツリーのスナップショットを取ります。インデックスやファイルには触れません。
- **未コミット**: 最後のコミット。未追跡のファイルも含みます。
- **ブランチ**: ブランチがリポジトリのデフォルトブランチから分かれた時点。プルリクエストと同じ見え方です。

各ファイルのすぐ下に差分が順に表示され、エージェントが編集を続けると差分も追従します。長い差分をスクロールしている間も、ファイル名は上部に残ります。ファイルは最初は折りたたまれ、変更されたファイルの一覧として表示されます: ファイル名をクリックすると差分を展開したり折りたたんだりできます。一覧の概要の隣のボタンで、すべてのファイルを展開します。展開されたファイルがあるときは、すべて折りたたみます。**未コミット**では、各セクションのタイトルにも同じボタンがあります。ファイルを右クリックすると、エディタやエディタペインで開けます。ペインにドラッグすると、そこで開きます。パネルの端をドラッグすると幅を変えられます。

パネルが狭い間は差分が統合表示され、広くなると左右に並べて表示されます。一覧の概要の右にあるボタンで 2 つを切り替えられ、その選択は `diff-layout` 設定に保存されます。その隣の折り返しボタンで、ファイルビューやエディタペインと同じく、長い行をパネルの幅で折り返します。さらにその隣の **ツリー表示** で、ファイルをフォルダごとに表示します: フォルダをクリックすると折りたたみます。別のフォルダだけを含むフォルダは、`src/app` のように 1 行にまとまります。未コミットでは、セクションのボタンがそのすべてのファイルにするように、フォルダのボタンでその中のファイルをステージ、ステージ解除、破棄できます。

### ターンをレビューする

**直前のターン**では、変更にポインタを合わせると 2 つのボタンが現れます:

- **元に戻す** は、ファイルに古い行を戻します。
- **保持** は、変更を確認済みにして隠します。

元に戻すは、セッションでエージェントが作業していない間だけ、そして差分の表示どおりのままのファイルにだけ使えます。エージェントの編集と競合しないためです。その間に変更されたファイルは、新しい差分として表示し直されます。

**ブランチ**では、変更には **元に戻す** だけがあります。ブランチが始まった時点の行をファイルに戻し、まだコミットしていない変更として残ります。

### レビューコメント

プルリクエストと同じように、エージェントの変更にコメントを付け、すべてのコメントをまとめてエージェントに送ります。**直前のターン**、**未コミット**、**ブランチ**では:

- 行番号にポインタを合わせて現れる **+** をクリックすると、その行にコメントできます。先に行番号をクリックし、Shift クリックで範囲を選んでおくと、選んだ行すべてにコメントできます。
- または、変更にポインタを合わせて **コメント** をクリックすると、その変更の選択した行に、選択がなければ変更全体にコメントできます。統合表示の差分で削除された行にコメントするには、この方法を使います。

行の下のボックスにコメントを書き、**コメント** をクリックするか、<kbd>⌘</kbd> <kbd>↩</kbd>（<kbd>Ctrl</kbd> <kbd>Enter</kbd>）を押します。<kbd>Esc</kbd> を押すと、コメントを書くのをやめます。コメントはその行の下に残り、編集や削除ができます。

ファイルの上のバーが、ワークツリーのコメントの数を示し、一覧します。コメントをクリックすると、そのファイルを該当の行で開きます。**エージェントに送る** は、ワークツリーで作業するエージェントのペインにコメントを 1 つのプロンプトとして貼り付け、送信します。各コメントには、ファイル、行番号、その行のテキストが付くので、行が移動した後でもエージェントは見つけられます。送ったコメントは、そのあと消えます。**プロンプトとしてコピー** は、代わりに同じプロンプトをコピーするので、別のエージェントに渡せます。**×**（**コメントを破棄**）は、それらを破棄します。コメントは Kero を終了するまで残ります。

## ステージとコミット

**未コミット**では、ファイルが 2 つのセクションに分かれて一覧されます。次のコミットにまだ入らない **変更** と、その下の、次のコミットに入る **ステージした変更** です。ステージしたファイルはすぐに移り、次のファイルがその場所に上がってきます。各ファイルのボタンで、ステージ、ステージの解除、変更の破棄ができます。破棄は先に確認します: 未追跡のファイルは削除され、削除したファイルは元に戻ります。セクションのタイトルのボタンは、そのすべてのファイルに同じことをします。**すべての変更をステージ** は競合を含めません。競合をステージすると解決済みになるためです。

ファイルを右クリックして **.gitignore に追加**、またはツリーのフォルダを右クリックして **フォルダを .gitignore に追加** を選ぶと、ワークツリーの最上位の `.gitignore` に追加されます。Git は、すでに追跡しているファイルを `.gitignore` に書いても追跡し続けます。そのため、追跡されているファイルや、追跡されているファイルを含むフォルダでは、追跡もやめるかどうかを Kero が確認します。追跡をやめたファイルは次のコミットでリポジトリから削除され、ディスクには残ります。

ファイルの一部をステージするには、差分の変更にポインタを合わせて **ステージ**（ステージした変更では **ステージを解除**）をクリックします。変更の **破棄** は、その古い行をファイルに戻します。変更の一部の行だけを扱うには、行番号をクリックし、Shift クリックで範囲を選びます。変更のボタンが **N 行をステージ**、**N 行のステージを解除**、**N 行を破棄** に変わります。Git LFS のように、保存するときに git のフィルタが変えるファイルは、ファイルごとにステージします。

<a id="committing"></a>

一覧の下のボックスにメッセージを書き、**コミット** をクリックするか、<kbd>⌘</kbd> <kbd>↩</kbd>（<kbd>Ctrl</kbd> <kbd>Enter</kbd>）を押します。ボックスのきらめきの **メッセージを書く** は、ステージした内容からメッセージを書かせます。書くのは、ペインのエージェントの会話のフォークです。変更した理由を知っていて、元の会話は変わりません。会話がなければ Claude Code か Codex を新しく実行します。`commit-message-command` を設定すると、別のコマンドで書きます。コマンドはシェルで実行され、プロンプトは標準入力で渡されます。中の `{session}` はペインのエージェントの会話の ID になるので、自分の起動コマンドでフォークできます: `cc -p --resume {session} --fork-session`。コミットの隣の矢印には、**コミットしてプッシュ**、**最後のコミットを修正**、**サインオフ**、**フックを飛ばす** があります。

## ブランチ、同期、スタッシュ

一覧の上のバーに、ワークツリーのブランチが表示されます。クリックするとブランチを切り替えられます: 入力して絞り込むか、新しいブランチの名前を入力して <kbd>Return</kbd>（<kbd>Enter</kbd>）を押します。そこでのブランチのメニューでは、切り替え、そこからのブランチ作成、専用のワークツリーのセッションで開く、名前の変更、削除、今のブランチへのマージ、今のブランチのリベースができます。コミットしていない変更があるまま切り替えると、先にスタッシュするか、持っていくかを尋ねます。

その隣の同期ボタンは、ブランチが遅れている分をプルしてから、進んでいる分をプッシュします。アップストリームのないブランチは公開します。**⋯** メニューにはほかの操作があります:

- **フェッチ**、**すべてのリモートからフェッチ**、**フェッチして削除済みを整理**。
- **プル**（git の設定どおり）、またはマージ、リベース、早送りのみのプル。
- **プッシュ**、**強制プッシュ**（リモートのブランチが最後にフェッチしたときのままの場合だけ上書きします）、**タグと一緒にプッシュ**。プッシュはそのブランチだけを、プッシュ先に送ります。
- **すべての変更をスタッシュ**、**ステージした変更をスタッシュ**、**メッセージを付けてスタッシュ…**。
- **新規ブランチ…**、**最後のコミットを取り消す**（変更はステージしたまま残ります）、**更新**。

プル、マージ、リベースは、コミットしていない変更を先にスタッシュし、終わると戻します。変更が競合したときは、スタッシュに残ります。パスワードが必要なフェッチ、プル、プッシュは **ターミナルで実行** とともに失敗します。同じコマンドをターミナルで実行し、git がパスワードを尋ねられるようにします。

エージェントがワークツリーで作業している間にファイルを変える操作（プルや破棄など）は、先に確認します。**終わってから** はエージェントが終わってから、**今すぐ** はすぐに実行します。ステージ、コミット、フェッチは確認しません。

## 履歴

エクスプローラーの **履歴** タブ、または <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>Y</kbd>（Windows と Linux では <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>Y</kbd>）で、ワークツリーのコミットをグラフで表示します。**すべて** ではすべてのブランチのコミットを、**ブランチ** ではそのブランチとアップストリーム、デフォルトブランチのコミットを表示します。ローカルのブランチとリモートのブランチは分けて表示されるので、同じコミットにあるブランチとリモートのブランチは両方見えます。まだプッシュしていないコミットには印が付きます。**フィルタ** でメッセージ、作成者、ハッシュからコミットを探せます。ファイルビューのファイルのメニューからは、そのファイルの履歴を表示できます。

コミットをクリックするとファイルが、ファイルをクリックすると差分が表示されます。ファイルのメニューでは、変更パネルと同じようにファイルを開けるほか、**ファイルの履歴を表示**でその履歴を表示できます。コミットしていない変更が一番上に、その下にスタッシュが表示され、適用、取り出し、破棄ができます。コミットのメニュー:

- **ハッシュをコピー**、**ブランチ名をコピー**。
- **チェックアウト**: そのコミットにあるブランチを、ブランチがなければコミット自体をデタッチしてチェックアウトします。
- **ここで新規ブランチ…**、**ここからワークツリーで新規セッション…**。
- **… を … にマージ**（マージコミットでも）、**… を … にリベース**、**… を … にインタラクティブリベース**。
- **チェリーピック**、**コミットをリバート**、**ここにリセット**: ソフトは以降の変更をステージしたまま、ミックスはステージせずに残し、ハードは破棄します。

### インタラクティブリベース

コミットやブランチのメニューの **… を … にインタラクティブリベース** は、そのコミット以降にブランチにあるコミットを、新しいものを上にして一覧します。それぞれの扱いをメニューかキーで決めます: <kbd>P</kbd> **Pick** はそのまま残し、<kbd>R</kbd> **Reword** は新しいメッセージにし、<kbd>E</kbd> **Edit** はそこで止まって変更でき、<kbd>S</kbd> **Squash** と <kbd>F</kbd> **Fixup** は下のコミットとまとめて、両方のメッセージか下のメッセージだけを残し、<kbd>D</kbd> **Drop** は取り除きます。コミットをドラッグするか、<kbd>Alt</kbd> <kbd>↑</kbd> と <kbd>Alt</kbd> <kbd>↓</kbd> で動かします。Reword にしたコミットの下には、新しい件名と説明を書くパネルが開きます。一覧の下の **コミット** と **変更** は、選んだコミットのメッセージとファイルです。

**現在の状態を一時ブランチにバックアップする** は、先に今の位置にブランチを作り、戻れるようにします。**リベース** は、ほかのリベースと同じくコミットしていない変更をスタッシュし、一覧どおりにコミットを適用し直します。Edit のコミットや競合で止まったら、**続行** で続けます。マージコミットを含む範囲は平らになってしまうので、この方法ではリベースできません。

## 競合

マージ、リベース、チェリーピック、リバートが競合で止まると、バーとコミットボックスの上にそう表示され、競合したファイルが **変更** に一覧されます。ファイルをエディタやターミナルで解決して **解決済みにする** をクリックするか、ファイルのメニューから片方の版を選びます: ブランチの名前で **main の版を使う** や **feature の版を使う** と表示されます。ファイルに加えた編集は失われるので、先に確認します。同じメニューの **マージエディタで開く** は、ファイルをエディタペインでマージエディタとして開きます: 上に 2 つの版が競合ごとにそろって並び、下にファイルがあり、編集できます。競合の上の **main の行を使う** や **feature の行を使う** にチェックすると、その版の行がファイルに入ります。両方にチェックすると、チェックした順に両方入ります。下のバーは残りの競合を数えて競合の間を移動し、そのメニューはすべての競合で片方の版の行を使うか、ファイルをテキストで表示します。競合がなくなると、**保存して解決済みにする** がファイルを保存してステージします。競合中のファイルは、解決済みにするまで、どのエディタペインでもこの形で開きます。ファイルのメニュー、またはコミットボックスの上の **エージェントで解決** は、ワークツリーで作業するエージェントに、すべての競合を解決してステージするよう頼みます。コミットはあなたに任されます。

競合がなくなると、**続行** でリベース、チェリーピック、リバートを続け、**マージをコミット** で git が用意したメッセージでマージをコミットします。**中止** は確認してから操作をやめ、始める前の状態に戻します。

## 専用のワークツリーで動くセッション

1 つのチェックアウトで並んで作業するエージェントは、互いの変更につまずきます。**セッション › ワークツリーで新規セッション…**（<kbd>⌘</kbd> <kbd>⌥</kbd> <kbd>T</kbd>）はブランチ名を尋ね、専用の git ワークツリーでセッションを開始します: リポジトリのデフォルトブランチから作った新しいブランチをチェックアウトするフォルダです。サイドバーのプロジェクトのメニューにもあり、そのプロジェクトのリポジトリのセッションを開始します。メニューバーのない Windows と Linux では、メニューバーのメニューは設定の隣にあるサイドバーの**メニュー**ボタン（⋯）にあります。

- ワークツリーはリポジトリ内の `.kero/worktrees/<branch>` に置かれます。Kero はそれを `.gitignore` ではなく `.git/info/exclude` で無視します。ほかの場所に置くには `worktree-dir` を設定します。
- デフォルトブランチではなく、今いるセッションから分岐するには `worktree-base = current` を設定します。
- 新しいワークツリーには git が追跡するファイルしかありません。`.claude/settings.local.json`、`CLAUDE.local.md`、`.env` のような無視されたファイルも持っていくには、Claude Code のワークツリーと同じく、リポジトリの最上位の `.worktreeinclude` に `.gitignore` の書式で並べます。Kero は一致する無視されたファイルをコピーします。ワークツリーにすでにあるファイルはそのままです。`node_modules` とほかのワークツリーは飛ばし、丸ごと無視されたフォルダには、`cache/keep.txt` のようにその中のパスを指すパターンがあるときだけ入ります。
- セッションはリポジトリのプロジェクトに入り、サイドバーにはそのブランチが表示されます。

セッションを閉じると、ワークツリーも削除するか尋ねます:

- **未コミットの変更がない:** 既定は「ワークツリーを削除」です。ブランチはマージ済みなら一緒に削除され、そうでなければコミットとともに残ります。
- **未コミットの変更がある:** Kero は失われるファイルの数を示し、既定は「ワークツリーを残す」です。
- **ほかのセッションがそのワークツリーで作業している:** ワークツリーは残り、Kero は尋ねません。

コマンドラインから:

```sh
kero new --worktree fix-login -- claude   # 専用のワークツリーで、新しいブランチのセッション
kero new --worktree fix-login --base dev  # dev から分岐する
kero close fix-login --remove-worktree    # 閉じて、ワークツリーを削除する
kero close fix-login --remove-worktree --force   # 未コミットの変更があっても
```

## ファイル

エクスプローラーの**ファイル**タブ、または <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>E</kbd>（Windows と Linux では <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>E</kbd>）で、今いるペインのワークツリー、リポジトリの外ならそのフォルダのファイルを表示します。リモートホストでは、そのホストのファイルです。

フォルダをクリックするか、<kbd>→</kbd> と <kbd>←</kbd> を押して開閉します。ファイルをクリックすると、ツリーの下に言語に合わせてハイライトされて開き、そのまま編集できます。<kbd>⌘</kbd> <kbd>S</kbd>（<kbd>Ctrl</kbd> <kbd>S</kbd>）で、改行コードを保ったまま保存します。編集したファイルは、ほかのファイルを見ている間も未保存の印を付けて開いたままです。ファイルの上の折り返しボタンで、長い行をビューの幅で折り返します。Markdown ファイルでは、**Markdown をプレビュー** で表示どおりに見られます。画像は画像として表示され、バイナリファイルと 4 MB を超えるファイルは開きません。`files-preview` がオフのときは、クリックはファイルを選ぶだけで、メニューの**プレビュー**でツリーの下に開きます。ターミナルの隣にファイルを置いておくには、[エディタペイン](./panes.md#editor-panes)で開きます。

ツリーの下にある **新規ファイル…** と **新規フォルダ…** のボタンで、選択したフォルダ、または選択したファイルのフォルダにファイルやフォルダを作成できます。名前か `src/util/new.go` のようなパスを入力して <kbd>Return</kbd>（<kbd>Enter</kbd>）を押すと作成され、<kbd>Esc</kbd> を押すとキャンセルします。新しいファイルはツリーの下に開きます。ほかのボタンではツリーを更新したり、フォルダを折りたたんだりできます。フォルダのメニューからは、そのフォルダに新しいファイルやフォルダを作成したり、そこでターミナルを開いたりできます（**ここで新しいターミナル**）。

ボタンの間の **フィルタ** 欄は、閉じたフォルダも含めてフォルダ全体からファイルとフォルダを名前で探し、それらを含むフォルダの中に表示します。スラッシュを入力すると、`src/main` のようにパスで探します。`node_modules` など git が無視するフォルダは、名前では見つかりますが、中は検索しません。<kbd>↓</kbd> か <kbd>Return</kbd>（<kbd>Enter</kbd>）で最初に見つかったファイルへ移動し、<kbd>Esc</kbd> でフィルタを消去すると、選んだファイルがツリー全体の中に表示されます。

保存は、開いたときのままのファイルにだけ書き込みます。その後にエージェントやほかのプログラムが変更していた場合は、そのことを知らせるので、編集を捨てて**再読み込み**するか、**上書き**します。自分の編集がない間は、ディスク上の変更に追従します。

ファイルをダブルクリックするか右クリックすると、エディタで開けます。エディタは `editor` 設定（`code` や `zed` など）、未設定ならシステムがそのファイルを開くアプリです。`files-double-click = pane` のときは、ダブルクリックでエディタペインに開きます。ドットファイルは `files-hidden` をオフにしない限り表示されます。フォルダのメニューからは、フォルダもエディタで開けます（未設定ならテキストファイルを開くアプリ）。メニューからは、ペインで開く、ほかのアプリで開く、エクスプローラーや Finder で表示する、パスやワークツリーからの相対パスをコピーすることもできます。

### ファイルへ移動

**セッション › ファイルへ移動…**（<kbd>⌘</kbd> <kbd>⇧</kbd> <kbd>N</kbd>、Windows と Linux では <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>N</kbd>）は、今いるペインのワークツリーのファイルを、名前の文字を順に入力して探します: `usvc` で `user_service.go` が見つかります。名前の一致が先で、パスの一致はその後に並びます。スラッシュを入力すると、`src/main` のようにパスだけで探します。<kbd>Return</kbd>（<kbd>Enter</kbd>）で、ファイルビューのファイルが開くのと同じようにエディタペインで開き、<kbd>⌘</kbd> <kbd>↩</kbd>（<kbd>Ctrl</kbd> <kbd>Enter</kbd>）では新しいペインで開きます。リポジトリでは、git が追跡しているファイルと、これから追跡するファイルを一覧するので、`node_modules` など `.gitignore` に書かれたものは含まれません。

## 検索

エクスプローラーの**検索**タブ、または <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>F</kbd>（Windows と Linux では <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>S</kbd>）で、ファイルビューに表示されるファイルのテキストを、それらがあるホスト上で検索します。入力が止まると検索が始まり、大文字と小文字は区別しません。ファイルが変わったときは、<kbd>Return</kbd>（<kbd>Enter</kbd>）でもう一度検索します。欄の隣のボタンは、**大文字と小文字を区別**、**単語単位で検索**、**正規表現を使う** で、正規表現は Go の構文で書きます。

見つかった行は、そのファイルの下に一覧され、見つかったテキストがハイライトされます。ファイルをクリックすると折りたたみ、行をクリックすると、そのファイルをその行でエディタペインに開きます。すでにそのファイルを表示しているエディタペインがあれば、そこで開きます。ファイルや行を右クリックすると、エディタやエディタペインで開けます。ペインにドラッグすると、そこでその行に開きます。git が無視するファイル、バイナリファイル、2 MB を超えるファイルは検索されず、検索結果には最初の 2,000 行が表示されます。

<a id="review"></a>

## レビュー

エクスプローラーの**レビュー**タブ、または <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>P</kbd>（Windows と Linux では <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>K</kbd>）は、今いるペインのリポジトリの GitHub 上のオープンなプルリクエストを一覧します。リポジトリがあるホストの [GitHub CLI](https://cli.github.com) で読むので、そこに `gh` をインストールしてサインインしておく必要があります。一覧はブランチのプッシュ先のリモート（たいていは `origin`）のものです。一覧の上のリポジトリ名で、GitHub 上の別のリモートを選べます。**オープン**、**自分の**、**レビュー待ち** で一覧を絞り込めます。各プルリクエストのブランチ、チェック、レビューが表示されます。プルリクエストをクリックすると、エクスプローラーに表示されます。隣の矢印は GitHub で開きます。**会話** には、説明、各レビュアーのレビューの状態 (承認、変更を要求、レビュー待ち)、チェック (クリックで一覧)、コメントとレビュー、そして行やファイルへのコメントのスレッドが表示されます。返信は、返信先のコメントの下に区切って表示されます。スレッドの場所をクリックすると **ファイル** で表示します。**ファイル** には、ベースと一緒に取得した変更が表示され、各ファイルの差分の行の下に、その行へのコメントが、差分の上にファイル全体へのコメントが表示されます。その後で行が変わったスレッドは、古いものとして会話にだけ表示されます。**会話を解決** は GitHub でスレッドを解決し、スレッドは一行に畳まれます。タブの隣の矢印で、自分のコメントと投稿済みのコメントを順に移動できます。リポジトリのワークツリーがプルリクエストのヘッドをチェックアウトしているとき (レビュー用のワークツリーなど) は、ファイルを右クリックして開くか、ペインにドラッグできます。そうでなければ、ファイルはディスクにないので開けません。

プルリクエストの**レビュー**は、エージェントにレビューさせます。クリックすると、プルリクエストのブランチを取得し、そのブランチの[専用のワークツリー](#sessions-in-their-own-worktree)の新しいセッションでエージェントを起動します。レビューごとに、プルリクエストを専用のブランチ `review/pr-<番号>`（次は `review/pr-<番号>-2`、…）にチェックアウトするので、同じプルリクエストを何度でもレビューでき、あなたのチェックアウトや別のワークツリーがそのブランチにあってもかまいません。変更ビューからそのブランチをプッシュすると、プルリクエストのブランチに送られます。git では `git push origin HEAD:<ブランチ>` を実行します。ワークツリーごとレビューを閉じると、プルリクエストのブランチにコミットがあれば、そのブランチも削除します。ボタンかプルリクエストを右クリックすると、今いるペインのエージェントに送るか、ペインのフォルダの新しいセッションでエージェントを起動するかを選べます。レビューが始まる前にプロンプトが表示され、編集できます。Kero はエージェントの準備ができたらプロンプトを入力します。90 秒たっても準備ができなければ、プロンプトをコピーします。

**リポジトリの設定…**（歯車）では、リポジトリごとにエージェントのコマンドとレビューのプロンプトを設定します。リポジトリによって使うスキルやツールが違うからです（`/code-review high {ticket}` など）。プロンプトの `{number}`、`{url}`、`{title}`、`{branch}`、`{base}`、`{author}` はプルリクエストの値になり、`{ticket}` はタイトル、説明、ブランチにある最初の課題キー（`PROJ-123` など）になります。どこにもなければ、レビューが入力を求めます。コマンドは、設定しなければ `claude` です。

<a id="draft-reviews"></a>

### 下書きのレビュー

エージェントは GitHub に投稿しません。コメントは、[Kero のスキル](./agents.md)が教える `kero pr comment` で、Kero が保持する下書きのレビューに入ります。Kero は、各コメントがプルリクエストの差分の行 (GitHub がコメントを受け付ける唯一の行)、またはプルリクエストが変更するファイルにあることを確認します。デフォルトのプロンプトでは、エージェントはまずプルリクエスト全体をレビューし、それからコメントを一つずつコードと照らし合わせて確認してから追加します。

コメントは、エージェントが追加するとすぐにプルリクエストの **ファイル** に **エージェント** の印付きで表示されます。変更ビューと同じように、どれでも編集・削除でき、行のガターから、またはヘッダーのコメントボタンでファイル全体に、自分のコメントも追加できます。エージェントのコメントのきらめきは、それについての質問をエージェントのペインに入力し、続きはあなたが書きます。プルリクエストの下のバーには、レビューの概要 (GitHub でのレビューの本文) と判定 (**コメント**、**承認**、**変更を要求**。自分のプルリクエストではコメントだけ) があります。**レビューを投稿** は確認してから、概要とコメントを 1 つのレビューとして投稿するので、作成者への通知は 1 回です。コメントがなくてもレビューできます。バーから承認したり、概要だけを残したりできます。レビューの一覧では、コメントか概要のある下書き、またはエージェントが作業中の下書きがあるプルリクエストに印が付きます。バーのメニューの **レビューを破棄…** は下書きを削除します。

<a id="pull-request-notifications"></a>

### 通知

Kero は 5 分ごとにプロジェクトの GitHub リポジトリを確認し、あなたにレビューを依頼する新しいプルリクエストを通知します。設定 › Git では、通知するプルリクエスト `pr-notify` (レビュー依頼、他の人が開いた新しいものすべて、またはなし。なしでは確認も止まります) と、確認する間隔 `pr-poll-interval` を設定します。通知をクリックすると、そのプロジェクトのセッションでプルリクエストが表示されます。Kero は確認したものを覚えているので、再起動しても再び通知しません。リポジトリの最初の確認は、開いているものを覚えるだけです。

<a id="new-pull-request"></a>

### 新しいプルリクエスト

**新しいプルリクエスト**は、今いるペインのブランチのプルリクエストを作ります。フォームにはマージ先のブランチが表示されます。最初はプッシュ先のリポジトリのデフォルトブランチです。クリックすると、別のブランチや別のリモートのリポジトリを選べます。デフォルトブランチが先頭で、その後は最近変更されたものから並び、入力すると絞り込めます。タイトルと説明の下には、プルリクエストに入るコミットと、それらが変更するファイルが一覧されます。ファイルをクリックすると差分が開きます。入るのはコミットだけです。フォームには、コミットしていないファイルの数と、プッシュ先にまだないコミットの数が表示されます。タイトルの隣のきらめきは、**メッセージを書く** がコミットメッセージを書くのと同じように、`commit-message-command` でタイトルと説明を書かせます。コミットが一つだけのブランチは、その件名をタイトルにします。

**プルリクエストを作成** は、プッシュ先にないコミットをプッシュしてから、`gh` でプルリクエストを作成して開きます。隣の矢印には **ドラフトとして作成** と **GitHub で表示** があります。**GitHub で表示** は、タイトルと説明を入力した状態で GitHub のプルリクエスト作成ページを開き、そこで仕上げられます。ブランチにすでにオープンなプルリクエストがあれば、フォームはそのリンクを表示します。

設定 › Git には、エージェントがコミットメッセージとプルリクエストを書く方法を指示するプロンプト `commit-message-prompt` と `pr-message-prompt` があります。変更するまでは Kero のものが表示され、**デフォルトに戻す** で戻せます。そこにあるレビューのプロンプト `pr-review-prompt` は、レビューするエージェントへの指示です。レビュータブの **リポジトリの設定…** で、この 3 つをリポジトリごとに置き換えられます。変更しないプロンプトは設定のものに従います。

## コマンドラインから

`kero diff` は、ペインの変更を `git diff` と同じ形式で、未追跡のファイルも含めて出力します:

```sh
kero diff                       # このペインの未コミットの変更
kero diff --turn                # エージェントが直前のターンで変更したもの
kero diff review --branch       # review セッションのデフォルトブランチ以降の変更
kero diff src/auth              # これらのパスだけ
```

`kero status --json` と `kero ls --json` には、各ペインのブランチと変更が `git` として含まれます。

`kero do` では、エージェントが作業内容を表示するように、パネルのビューを表示できます。**設定 › エージェント** の **リモート操作** が必要です:

```sh
kero do changes.show                 # 変更ビュー
kero do files.show                   # ファイルビュー
kero do files.show path=src/main.go  # このファイルまたはフォルダを開いた状態
kero do search.show query=TODO       # 検索ビューで TODO を検索した状態
```

## オフにする

`git-status = false` を設定するか、設定で **git の状態を表示** をオフにすると、Kero はリポジトリで git を実行しなくなります。
