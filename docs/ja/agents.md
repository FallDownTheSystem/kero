# コーディングエージェント

Kero で動くエージェントは、あなたと同じように `kero` コマンドを使えます: 下のペインで開発サーバーを起動し、2 つ目のエージェントにレビューを任せ、テストを待ち、行き詰まったらあなたに知らせます。

<a id="install-the-skill"></a>

## スキルをインストールする

```sh
kero skill setup
```

これで 2 つのものがインストールされます:

- エージェントに CLI を教える **スキル**。Claude Code は `~/.claude/skills/kero` から、Codex、OpenCode などのエージェントは `~/.agents/skills/kero` から読み込みます。
- エージェントがセッションを始めるときに実行される **フック**。エージェントに、どの Kero セッションとペインにいるかを伝えるので、それを調べる手間が省けます。また、名前のないセッションに `fix-login-redirect` のようなタスクにちなんだ名前を付けさせるので、あなたが付ける必要はありません。さらに、エージェント自身のセッションを Kero に伝えるので、再起動のあとなど kerod が再起動したとき、エージェントは[会話を再開](./sessions.md#kerod)します。

フックは、インストールされているエージェントごとに、それぞれが探す場所に置かれます:

| エージェント | フックの場所                                          |
| ------------ | ----------------------------------------------------- |
| Claude Code  | `~/.claude/settings.json` の `SessionStart` フック     |
| Codex        | `~/.codex/hooks.json` の `SessionStart` フック         |
| Pi           | 拡張機能 `~/.pi/agent/extensions/kero.ts`              |
| OMP          | 拡張機能 `~/.omp/agent/extensions/kero.ts`             |
| OpenCode     | プラグイン `~/.config/opencode/plugins/kero`           |

`CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`PI_CODING_AGENT_DIR`、`PI_CONFIG_DIR`、`XDG_CONFIG_HOME` でエージェントのファイルの場所が変わっている場合、Kero はそれに従い、各設定ファイルのほかの部分はそのままにします。

1 つのエージェントだけをセットアップするには、`--agent` に `claude`、`codex`、`pi`、`omp`、`opencode` のいずれかを渡します。セットアップは一度だけです: スキルは Kero 自身のコピーへのリンクで、Kero のアップデートに合わせて更新されます。Pi、OMP、OpenCode のプラグインも Kero が最新に保ちます。`kero skill status` で、各部分が最新かどうかがわかります。

```sh
kero skill status    # インストール済みのものと、それが最新かどうか
kero skill show      # スキルを出力
kero skill remove    # スキルとフックをアンインストール
```

フックが働くのはセットアップ後に始めたエージェントのセッションだけで、エージェントが先に確認を求めることもあります:

- **Claude Code** は、信頼したフォルダでのみフックを実行します。
- **Codex** は新しいフックの承認を求めます: `/hooks` で Kero のフックを承認してください。
- **OpenCode** は、バックグラウンドサービスの起動時にプラグインを読み込みます: 作業中のセッションがないときに、一度 `opencode service restart` を実行してください。

OpenCode はエージェントのコマンドをペインではなくバックグラウンドサービスで実行するので、`KERO_SESSION` と `KERO_PANE` がありません。代わりに Kero がエージェントにペインを伝え、エージェントはそれを対象として指定します。同じ理由で、OpenCode のエージェントからの `kero report` はそのペインに届きません。

Kero の外では、フックは何もしません。

## エージェントにできること

自分の横で何かを動かす:

```sh
kero split --down -- npm run dev
kero new -n review -- claude
```

それを操作して結果を読む:

```sh
kero prompt review "review the changes in src/auth"
kero wait tests --for idle,error --timeout 10m
kero read tests -n 60
```

自分の横でテストを実行して、失敗した内容を読む:

```sh
pane=$(kero split --down -- go test ./...)
kero wait "$pane" --exit || kero read "$pane" -n 80
```

`git worktree list` にはない情報つきでリポジトリのワークツリーを見る（各ワークツリーのセッション、Kero が作ったか、削除で失うもの、自動クリーンアップがどうするか）。自分のセッションのワークツリー、セットアップ、プルリクエストを確かめる。自分のセッションを会話ごと新しい git ワークツリーに移し、ターンの終わりにそこで続ける（[詳しく](./changes.md#moving-a-session-into-a-worktree)）:

```sh
kero worktree list
kero worktree status
kero worktree handoff fix-login --prompt "go on with the fix"
```

プルリクエストを扱う: [レビューガイド](./changes.md#review-guides)を書き、セッションにリンクされたプルリクエストを見ます。Kero はそれを見守り、チェックが失敗すると「Kero PR watch:」で始まるメッセージをエージェントのプロンプトに入力します。頼まれれば、マージ、更新、チェックアウトもします（[すべて](./cli.md)）:

```sh
kero pr guide stop src/queue.go:10-42 --title "The new queue" "Why it exists."
kero pr status                  # リンクされたプルリクエスト: チェック、コンフリクト
kero pr update-branch --rebase
kero pr merge --squash          # 頼まれたときだけ: マージは取り消せません
kero pr checkout 123 --worktree -- claude
```

状況をあなたに伝える:

```sh
kero report working "Migrating the database" --progress 40
kero report blocked "Approve the production deploy?"
kero report done "Deployed to staging"
```

`blocked` の報告でセッションは*待機中*になり、あなたに通知されます。エージェントがこれを使うのは、あなたなしでは続けられないときだけにしてください。

<a id="orchestrator-sessions"></a>

## オーケストレーターセッション

オーケストレーターは、作業を計画し、そのための別のセッション（**子**）を開始して見守るエージェントセッションです。あなたが話しかけるのはオーケストレーターだけです。[新規セッションのダイアログ](./sessions.md#new-session-dialog)で **統括役** と任意の **目標** を選ぶか、次のように開始します:

```sh
kero new --orchestrator --goal "新しいログインページを出す"
kero orchestrator <session>       # セッションをオーケストレーターにする（off で元に戻す）
```

選んだエージェント（なければ `default-agent`）は役割プロンプトから始めます: 計画して任せる、`kero new` で子を開始する、答えられることは自分で答え、必要なことだけあなたに尋ねる、対応の要らない報告には要約せず「OK」とだけ返す、目標を見失わない。プロンプトは **設定 › エージェント › オーケストレーター**（`orchestrator-prompt`）で置き換えられます。`{goal}` は目標、`{agent}` は既定のエージェントです。

- **子。** オーケストレーターが `kero new` で開始したセッションはその子になり、同じプロジェクトに入ります。階層は 1 段だけです: 子の `kero new` は孫ではなく、同じオーケストレーターの別の子を開始します。`kero new --parent <session>` でオーケストレーターを指定し、`--parent none` でどれにも属さないセッションを開始します。`orchestrator-max-children` で同時に動く子の数を制限できます。
- **報告。** 子が入力待ちになる、作業のあとアイドルになる、失敗する、終了する、閉じられると、Kero はオーケストレーターのプロンプトが空いたときにそれを入力します。近いタイミングのものは 1 つのメッセージにまとめ、2 秒未満の状態は報告しません。子は `kero report --to-parent "<要約>"` で自分の結果を送れます。オーケストレーター自身が閉じた子は報告しません。報告はオーケストレーターのプロンプトが空くまで待ち、その間に閉じられた子の状態の行は取り除かれます。閉じられたことと、子が送った要約だけが届きます。
- **サイドバー。** オーケストレーターの行には印が付き、ツールチップに目標が出ます。子は移動しても常にそのすぐ下に ↳ 付きで並びます。シェブロンで子を折りたためます（Kero が覚えます）。折りたたむと、対応が必要な子の数を表示します。
- **通知。** 子の変化はサイドバーに出ますが、通知せず、Dock のバッジにも数えません。それはオーケストレーターが受け取ります。オーケストレーター自身の入力待ちとエラーは通常どおり通知します。`notify-children`（**設定 › 通知**）で子の通知を戻せます。
- **子に直接話しかける**こともできます。クリックして入力するだけです。オーケストレーターは次の報告でそれを知ります。
- **閉じる。** オーケストレーターを閉じると、子も閉じるか、独立したセッションとして残すかを尋ねます（`kero close <orchestrator> --children` は子も閉じます）。専用のワークツリーを持つ子は、それを[クリーンアップ](./changes.md)に任せて残します。子を閉じるとツリーから外れ、ワークツリーの子はいつもどおりワークツリーについて尋ねます。

`kero ls` はオーケストレーターと子に印を付け、`kero status <orchestrator>` は目標と子を、`kero status <child>` はそのオーケストレーターを表示します。

## ヘルパーエージェント Ama

Ama は Kero を代わりに操作してくれるエージェントです。名前はニホンアマガエル（雨蛙、*amagaeru*）から来ています。セッションサイドバー下部のカエルをクリックするか、**Ctrl+Shift+A**（macOS では **⇧⌘A**）を押すか、**表示 › Ama** を選び、たとえば次のように頼みます:

- 「プロジェクト X のオープンな PR すべてにコードレビューを始めて」
- 「古いワークツリーを全部片付けて」
- 「このフォルダの新しいプロジェクトを追加して、この目標でオーケストレーターを始めて」
- 「どのセッションが私を待ってる？」
- 「プロジェクト Y の終わったセッションを全部閉じて」

Ama は本物のターミナルで動く普通のエージェントセッションです。デフォルトのエージェント、または **設定 › エージェント › Ama** で選んだエージェント（`ama-agent`）を実行します。プロジェクトの作業は自分では行わず、実際の作業には適切なプロジェクトでセッションかオーケストレーターを始めます。どのプロジェクトにも属さず、Kero の設定ファイルの隣にある専用フォルダ `ama`（`~/.config/kero/ama`）で動きます。サイドバーには表示されず、「対応が必要」にも数えられず、通知も送りません。Ama が応答を待っている間はカエルにドットが付きます。

ポップオーバーを閉じても Ama は動き続け、次に開くと同じ会話に戻ります。ポップオーバーでは:

- **新しいチャット**で新しい会話を始めます。
- **履歴**で Ama の過去の会話に戻ります。
- **クリア**で画面を消去します。

Kero は Ama の指示をフォルダに `CLAUDE.md` と `AGENTS.md` として書き、Kero の更新時に書き直します。あなた自身の指示は隣の `USER.md` に書きます。このファイルは Kero が一度だけ作り、以後変更しません。Ama はこれを先に読みます。**設定 › エージェント › Ama** から開けます。Ama が起動する前に、Kero は `kero skill setup` と同じように Ama のエージェントへスキルもインストールします。

Ama は [Kero を管理する](./cli.md#managing-kero) のコマンドで Kero を管理します。

## リモート操作

**リモート操作** がオン（デフォルト、**設定 › エージェント**）なら、エージェントはアプリ自体も操作できます: `kero focus` でセッションを表示したり、`kero do` でメニューのアクションを実行したりします。エージェントを自分のセッションだけにとどめるには、`remote-control = false` でオフにします。

Ama にはリモート操作は不要です。kerod は Ama のペインにだけ秘密の値 `$KERO_AMA` を渡します。これは Ama のセッションを、kerod が起動するたびに作り直す鍵でハッシュしたものです。`kero do`、`kero focus`、`kero browser` はこれを渡し、kerod がそれを Ama のものと確かめたときだけ、アプリはリモート操作なしで操作を実行します。ファイルには保存されず、他のペインには渡されず、他のマシンの kerod には意味がないため、他のエージェントについては引き続きリモート操作の設定で決まります。

## 環境変数

すべてのペインには次の変数があります:

| 変数           | 値                             |
| -------------- | ------------------------------ |
| `KERO_SESSION` | ペインのセッションの ID        |
| `KERO_PANE`    | ペインの ID                    |

スクリプトが Kero の中で動いているかどうかは、`$KERO_PANE` で確認できます。
