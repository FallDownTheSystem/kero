# アシスタント

アシスタントは、プロジェクトに属さないあなたのエージェントです。名前、色、アバター、役割、何をするか・何を見守るか、そして Kero が起こして実行させる確認を持ちます。毎朝 Jira のチケットを追うもの、メールを読むもの、毎週月曜にマージ済みのブランチを片付けるもの、まだ答えていない質問を思い出させるもの、などです。アシスタント自身にツールはありません。マシンがエージェントに与えるもの（MCP サーバー、CLI、スキル）を使います。

## アシスタントビュー

セッションサイドバー上部の切り替えで **セッション** と **アシスタント** を切り替えます（**表示 › セッション／アシスタント**）。アシスタントがあなたを待っている間はドットと数が、未読の知らせがある間は緑のドットが付きます。

ビューはアシスタントを **グループ** ごとにまとめ、グループのないものを先に表示します。各行にはアバター、名前、セッションの状態が表示され、2 行目にはステータス行（なければ最後のレポートの 1 行目、それもなければ役割）と、右に次回の確認時刻、**一時停止中**、または問題が表示されます。アシスタントが開始したセッションはその下に表示されます。

アシスタントをクリックすると、そのセッションがほかのセッションと同じようにウィンドウに表示されます。セッションがなければ開始します。**+** または **セッション › 新しいアシスタント…** で追加します。右クリックすると **今すぐ確認を実行**、**新しいチャット**、**確認を一時停止**、**編集…**、**フォルダを表示**、**セッションを閉じる**、**アシスタントを削除…** があります。セッションビューにはアシスタントのセッションは表示されませんが、アシスタントが開始したセッションはそれぞれのプロジェクトに表示されます。

## 作成する

ダイアログでは **名前**、**役割**（「Jira のチケットを前に進める」のような 1 行）、**色**（8 色のいずれか、またはその後ろのカラーウェルで選ぶ好きな色）、**アバター**（頭文字、20 種類のグリフ（記号 9 種と動物 11 種）、または 2 MB までの PNG・JPEG・GIF・WebP 画像）、何をするか・何を見守るか、**グループ**、**確認**、**エージェント** と **引数** を指定します。作成すると、そのセッションが開始して表示されるので、エージェントが最初に尋ねること（フォルダを信頼するかなど）に答えてください。

確認は無人で実行されます。許可を求めるエージェントはあなたを待ちます。Claude Code の `--allowedTools` や `--permission-mode` のように、確認に必要なことを許可する引数を与えてください。

## 確認

確認は、時刻を指定した **毎日**、曜日と時刻を指定した **毎週**、または **Kero の起動時** で、それぞれ確認する内容を持ちます。確認はこのコンピュータで Kero が実行中のときだけ、ローカル時刻で行われます。Kero は各確認の実行時刻を記録します。Kero が閉じていた間やコンピュータの電源が切れていた間に逃した確認は、何回逃しても、次に Kero が実行中になったときに一度だけ実行されます。**Kero の起動時** の確認は kerod が起動するたびに一度、ただし 4 時間に一度までで、アップデートのための再起動で繰り返されることはありません。kerod をサービスとしてインストールしていれば（`kero daemon install-service`）、Kero のウィンドウを閉じていても確認は行われます。

確認は、アシスタントのエージェントがプロンプトに戻ったときに「Kero: message from your schedule:」として、予定されていた確認と予定時刻とともに届きます。作業中のアシスタントにはターンの後に届きます。セッションがなければ、Kero が先にセッションを開始します。

## レポートと通知

アシスタントは各確認の最後に、Kero のすべてのエージェントの報告と同じ 4 つの部分（Result、Not done、Where、Next）で `kero assistants report` によりレポートします。Kero は最新の 10 件を保持します。「Waiting on you:」で始まるレポートは、あなたがそのセッションで答えるか次のレポートが来るまで、アシスタントをその質問で待機中にします（「あなたが必要」に数えられます）。

Kero は **通知** の設定に従って、アシスタントがあなたを待っているときや失敗したとき、そして確認を終えたときに通知します（「Jira が確認を終えました」とレポートの結果）。それ以外のターン（開始したセッションへの返答など）は未読の印だけを付けます。

## フォルダ

各アシスタントには、Kero の設定ファイルの隣の `assistants/<id>` にフォルダがあります:

- `CLAUDE.md` と `AGENTS.md`: Kero が役割、見守る内容、確認から書き、編集のたびに書き直す指示。
- `USER.md`: あなた自身の指示。Kero は一度だけ作り、二度と変更しません。
- `MEMORY.md`: 確認やチャットをまたいでアシスタントが残すメモ。Kero は変更しません。

セッションはこのフォルダで動き、そのペインには ID を値とする `KERO_ASSISTANT` が渡されます。アシスタントを削除しても、一緒に削除しない限りフォルダは残ります。

## アシスタントが開始するセッション

リポジトリでの作業や長くかかる作業のために、アシスタントはプロジェクトかフォルダを指定して `kero new` でセッションを開始し、それが子になります。[オーケストレーター](./orchestrators.md)と同じように子の様子を受け取り、`kero message` でメッセージを送ります。子が通知するかどうかは **オーケストレーターのセッション**（設定 › 通知）で決まり、数は `orchestrator-max-children` で制限されます。

## コマンドラインから

```sh
kero assistants                         # 各アシスタントの状態と次回の確認
kero assistants news --json             # 最後のレポートと、あなたを待っているもの
kero assistants create Jira --role "Keeps my Jira tickets moving" \
    --check 'daily@09:00=What moved in my tickets since yesterday?'
kero assistants run jira                # 今すぐ確認を実行
kero assistants pause jira
```

`kero assistants help` ですべてが表示されます。[Ama](./ama.md) は `kero assistants news` から「アシスタントから何か知らせは？」に答えます。
