# プルリクエスト

Kero は、リポジトリがあるホストの [GitHub CLI](https://cli.github.com)（`gh`）を通して、GitHub 上のリポジトリのプルリクエストを扱います。そのため、そこに `gh` をインストールしてサインインしておく必要があります。どの操作もあなたとして `gh` を使うので、できることは GitHub が決め、Kero はそれだけを表示します。

<a id="review"></a>

## レビュータブ

右サイドバーの**レビュー**タブ、または <kbd>⌥</kbd> <kbd>⌘</kbd> <kbd>P</kbd>（Windows と Linux では <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>K</kbd>）は、今いるペインのリポジトリのオープンなプルリクエストを一覧します。一覧はブランチのプッシュ先のリモート（たいていは `origin`）のものです。一覧の上のリポジトリ名で、GitHub 上の別のリモートを選べます。**オープン**、**自分の**、**レビュー待ち** で一覧を絞り込めます。各プルリクエストのブランチ、チェック、レビューが表示されます。プルリクエストを右クリックすると、マージ、ブランチを更新、レビュー可能にする／ドラフトに戻す、クローズができます。

## プルリクエストのページ

プルリクエストをクリックすると、ペインの横のビューアに表示されます。隣の矢印は GitHub で開きます。**会話** には、説明、各レビュアーのレビューの状態 (承認、変更を要求、レビュー待ち)、チェック (クリックで一覧)、コメントとレビュー、そして行やファイルへのコメントのスレッドが表示されます。返信は、返信先のコメントの下に区切って表示されます。スレッドの場所をクリックすると **ファイル** で表示します。**ファイル** には、ベースと一緒に取得した変更が表示され、各ファイルの差分の行の下に、その行へのコメントが、差分の上にファイル全体へのコメントが表示されます。その後で行が変わったスレッドは、古いものとして会話にだけ表示されます。**会話を解決** は GitHub でスレッドを解決し、スレッドは一行に畳まれます。タブの隣の矢印で、自分のコメントと投稿済みのコメントを順に移動できます。リポジトリのワークツリーがプルリクエストのヘッドをチェックアウトしているとき (レビュー用のワークツリーなど) は、ファイルを右クリックして開くか、ペインにドラッグできます。そうでなければ、ファイルはディスクにないので開けません。

<a id="reviewing-with-an-agent"></a>

## エージェントでレビューする

プルリクエストの**レビュー**は、エージェントにレビューさせます。クリックすると、プルリクエストのブランチを取得し、そのブランチの[専用のワークツリー](./worktrees.md)の新しいセッションでエージェントを起動します。レビューごとに、プルリクエストを専用のブランチ `review/pr-<番号>`（次は `review/pr-<番号>-2`、…）にチェックアウトするので、同じプルリクエストを何度でもレビューでき、あなたのチェックアウトや別のワークツリーがそのブランチにあってもかまいません。変更タブからそのブランチをプッシュすると、プルリクエストのブランチに送られます。git では `git push origin HEAD:<ブランチ>` を実行します。ワークツリーごとレビューを閉じると、プルリクエストのブランチにコミットがあれば、そのブランチも削除します。ボタンかプルリクエストを右クリックすると、今いるペインのエージェントに送るか、ペインのフォルダの新しいセッションでエージェントを起動するかを選べます。レビューが始まる前にプロンプトが表示され、編集できます。新しいセッションのエージェントにはプロンプトをコマンドの引数として渡すので、何も入力されることなくすぐにレビューを始めます。今いるペインのエージェントにはプロンプトを貼り付けます。

プルリクエストをレビューするセッションは、サイドバーで**レビュー**と表示され、プルリクエストの上の**レビューエージェント**に、サイドバーと同じ状態とエージェントの最後のメッセージとともに一覧されます。クリックするとそのセッションに移動します。メニューからプルリクエストを表示したり、セッションを閉じたりできます（ワークツリーも削除するか確認します）。レビューエージェントのあるプルリクエストには、行とページで**レビュー**の代わりに**エージェント**が表示され、エージェントに移動します。セッションを閉じてもワークツリーを残したレビューは一覧に残り、そのワークツリーで再レビューするか、削除できます。**ワークツリーを削除…**は先に確認し、失われる変更ファイルの数を示します。すでにレビューのあるプルリクエストをレビューすると、そのエージェントを開くか、新しいワークツリーではなくそのワークツリーでレビューするかを選べます。

<a id="repository-setup"></a>

## リポジトリの設定

レビュータブの歯車、**リポジトリの設定…** では、リポジトリごとにエージェントのコマンドとレビューのプロンプトを設定します。リポジトリによって使うスキルやツールが違うからです（`/code-review high {ticket}` など）。プロンプトの `{number}`、`{url}`、`{title}`、`{branch}`、`{base}`、`{author}` はプルリクエストの値になり、`{ticket}` はタイトル、説明、ブランチにある最初の課題キー（`PROJ-123` など）になります。どこにもなければ、レビューが入力を求めます。コマンドは、設定しなければ `claude` です。Kero はプロンプトを 1 つの引数としてコマンドの後に渡します（Claude Code や Codex は最初のプロンプトをこう受け取ります）。別の位置で受け取るコマンドなら、`codex exec {prompt} --full-auto` のように `{prompt}` を置きます。コマンドでもプルリクエストのプレースホルダーが使えます。

ここではリポジトリの既定のマージ方法 `repo-merge-method` も設定でき、そのリポジトリのコミットメッセージ、プルリクエスト、レビューのプロンプトを置き換えられます（[プロンプト](#prompts)）。

## チェックアウト

プルリクエストのメニューとページにある**チェックアウト**は、エージェントなしで、`gh pr checkout` と同じくプルリクエストの名前のブランチにチェックアウトします。プルリクエスト自身のブランチ（プッシュするとプルリクエストに反映されます）、フォークからのものなら `pr-<number>` です。**ここにチェックアウト**は、いまいるペインのワークツリーにチェックアウトします。そのワークツリーにコミットしていない変更があるあいだはチェックアウトしないので、先にコミットするかスタッシュするか、新しいワークツリーにチェックアウトしてください。すでにあるブランチは、プルリクエストより遅れていれば追いつかせ、独自のコミットがあればそのまま残します。**新しいワークツリーにチェックアウト**は、そのブランチの[専用のワークツリー](./worktrees.md)でセッションを始めます。プルリクエストをすでに持つワークツリー（そのブランチ、そこへプッシュするブランチ、またはレビューのワークツリー）があれば、代わりにそこへ移動します。そこで動くセッションがあればそのセッションへ、なければ新しいセッションを開きます。

<a id="merging-and-other-actions"></a>

## マージとほかの操作

プルリクエストのページでは、タイトルの下に、そのままマージできるか、できないならその理由（競合、必須のレビューやチェック、ベースより遅れたブランチ、ドラフト）が表示されます。ボタンは、マージ、ドラフトのレビュー可能化、クローズしたものの再オープン、マージ済みのもののブランチ削除またはリバートを行います。隣の **⋯** には残りの操作があります：**マージ…**、**自動マージを有効にする…** または **自動マージを無効にする**、**ブランチを更新**（リベースでも）、**ドラフトに戻す**、**プルリクエストをクローズ…**、**リバート…**、**ブランチを削除…**。**マージ** は、リポジトリが許す方法（スカッシュ、マージコミット、リベース）のどれでマージするか、マージ後にブランチを削除するかを尋ねます。見ていたコミットでのみマージするので、その後に push があれば止まります。条件を満たしていない間は、**自動マージを有効にする** で条件を満たしたときに GitHub がマージします。メンテナーの承認を待つワークフロー実行があるフォークのプルリクエストには **承認** があり、フォークのコードを実行するので先に確認を求めます。

**マージ** の初期値は、[リポジトリの設定](#repository-setup)で設定するリポジトリの既定のマージ方法 `repo-merge-method` です。別の方法でマージするときに **このリポジトリの既定にする** をチェックしても設定されます。設定がなければ、スカッシュ、マージコミット、リベースのうちリポジトリが許す最初のものです。

<a id="draft-reviews"></a>

## 下書きのレビュー

エージェントは GitHub に投稿しません。コメントは、[Kero のスキル](./agents.md)が教える `kero pr comment` で、Kero が保持する下書きのレビューに入ります。Kero は、各コメントがプルリクエストの差分の行 (GitHub がコメントを受け付ける唯一の行)、またはプルリクエストが変更するファイルにあることを確認します。デフォルトのプロンプトでは、エージェントはまずプルリクエスト全体をレビューし、それからコメントを一つずつコードと照らし合わせて確認してから追加します。

コメントは、エージェントが追加するとすぐにプルリクエストの **ファイル** に **エージェント** の印付きで表示されます。変更タブと同じように、どれでも編集・削除でき、行のガターから、またはヘッダーのコメントボタンでファイル全体に、自分のコメントも追加できます。エージェントのコメントのきらめきは、それについての質問をエージェントのペインに入力し、続きはあなたが書きます。プルリクエストの下のバーには、レビューの概要 (GitHub でのレビューの本文) と判定 (**コメント**、**承認**、**変更を要求**。自分のプルリクエストではコメントだけ) があります。**レビューを投稿** は確認してから、概要とコメントを 1 つのレビューとして投稿するので、作成者への通知は 1 回です。コメントがなくてもレビューできます。バーから承認したり、概要だけを残したりできます。レビューの一覧では、コメントか概要のある下書き、またはエージェントが作業中の下書きがあるプルリクエストに印が付きます。バーの **下書きを開始** は、エージェントなしで下書きを始めます。自分のエージェントが `kero pr comment --pr <番号>` でコメントを追加できます。バーのメニューの **レビューを破棄…** は下書きを削除します。

<a id="review-guides"></a>

## レビューガイド

プルリクエストの **ガイド** タブは、行ごとに読まなくても理解できるようにする案内です。概要のあと、読む順にストップが並び、各ストップは読むべき行をメモ付きで示します。**ガイドを書く** は、レビューと同じくプルリクエストのワークツリーでエージェントに書かせます。指示は `pr-guide-prompt` (設定 › Git) で、エージェントは `kero pr guide` で書き、GitHub には何も送られません。タブはストップを 1 つずつ、その行の抜粋とともに表示し、上にストップの一覧、**次のストップ** があります。**要確認** の印があるストップは、メンテナーにしか判断できない点です。**差分全体** はストップのファイル全体を表示し、ファイルタブと同じようにコメントできます。**コメント** はストップの行に下書きレビューのコメントを始め、**エージェントに質問** はストップについての質問をエージェントのペインに入力します。プルリクエストが変わる前に書かれたガイドはそう表示され、**ガイドを書き直す** があります。メニューの **ガイドを破棄** で削除できます。下書きのレビューは残ります。

<a id="pull-request-notifications"></a>

## 通知

Kero は 5 分ごとにプロジェクトの GitHub リポジトリを確認し、あなたにレビューを依頼する新しいプルリクエストを通知します。設定 › Git では、通知するプルリクエスト `pr-notify` (レビュー依頼、他の人が開いた新しいものすべて、またはなし。なしでは確認も止まります) と、確認する間隔 `pr-poll-interval` を設定します。通知をクリックすると、そのプロジェクトのセッションでプルリクエストが表示されます。Kero は確認したものを覚えているので、再起動しても再び通知しません。リポジトリの最初の確認は、開いているものを覚えるだけです。

<a id="a-session-s-pull-request"></a>

## セッションのプルリクエスト

セッションは自分のプルリクエストを知っています。セッションのブランチがプッシュされ、GitHub に開いたプルリクエストがあると、Kero はそれをセッションにリンクします。**新しいプルリクエスト** で作ったときはすぐにリンクします。別のブランチに移るとリンクは外れます。手でリンクすることもでき、その場合はブランチが変わっても置き換わりません。プルリクエストのページの見守りボタンで今いるセッションにリンクまたはリンク解除でき、`kero pr link` と `kero pr unlink` でも同じことができます。セッションのツールチップにはチェックの状況が出て、メニューから表示やリンク解除ができます。

セッションが開いている間、Kero は 1 分ごとにそのプルリクエストを見守り、チェックが失敗したときやコンフリクトでマージできないときに、[エージェント自身の受け取り方法](./agents.md#how-agents-get-keros-messages)を通じてセッションのエージェントにメッセージを送り、起こします。メッセージは「Kero PR watch:」で始まります。エージェントはプロンプトに戻ってから受け取り、作業中やあなたに質問している間は受け取りません。設定 › Git の `pr-watch-wake` で何が起こすかを設定します。`all` ではチェックが成功したときと、あなた以外のコメントやレビューが来たときにも起こします。`failures` は失敗したチェックとコンフリクトだけ、`off` は何もしません。コメントだけで起こすのは 1 つのプルリクエストにつき最大 10 回なので、エージェントに返信するボットが延々と続けることはありません。エージェントのいないセッションでは、代わりにあなたに通知します。

<a id="new-pull-request"></a>

## 新しいプルリクエスト

**新しいプルリクエスト**は、今いるペインのブランチのプルリクエストを作ります。フォームにはマージ先のブランチが表示されます。最初はプッシュ先のリポジトリのデフォルトブランチです。クリックすると、別のブランチや別のリモートのリポジトリを選べます。デフォルトブランチが先頭で、その後は最近変更されたものから並び、入力すると絞り込めます。タイトルと説明の下には、プルリクエストに入るコミットと、それらが変更するファイルが一覧されます。ファイルをクリックすると差分が開きます。入るのはコミットだけです。フォームには、コミットしていないファイルの数と、プッシュ先にまだないコミットの数が表示されます。タイトルの隣のきらめきは、**メッセージを書く** がコミットメッセージを書くのと同じように、`commit-message-command` でタイトルと説明を書かせます。コミットが一つだけのブランチは、その件名をタイトルにします。

**プルリクエストを作成** は、プッシュ先にないコミットをプッシュしてから、`gh` でプルリクエストを作成して開きます。隣の矢印には **ドラフトとして作成** と **GitHub で表示** があります。**GitHub で表示** は、タイトルと説明を入力した状態で GitHub のプルリクエスト作成ページを開き、そこで仕上げられます。ブランチにすでにオープンなプルリクエストがあれば、フォームはそのリンクを表示します。

<a id="prompts"></a>

## プロンプト

設定 › Git には、エージェントがコミットメッセージとプルリクエストを書く方法を指示するプロンプト `commit-message-prompt` と `pr-message-prompt` があります。変更するまでは Kero のものが表示され、**デフォルトに戻す** で戻せます。そこにあるレビューのプロンプト `pr-review-prompt` は、レビューするエージェントへの指示で、`pr-guide-prompt` はガイドを書くエージェントへの指示です。レビュータブの **リポジトリの設定…** で、最初の 3 つをリポジトリごとに置き換えられます。変更しないプロンプトは設定のものに従います。

## コマンドラインから

```sh
kero pr list -p api --json          # リポジトリのオープンなプルリクエスト
kero pr review 123 -p api           # レビュータブと同じく、ワークツリーでエージェントがレビューする
kero pr review 123 -p api --guide   # エージェントがレビューガイドを書く
kero pr checkout 123 --worktree -- claude
kero pr state 123                   # オープンか、ドラフトか、マージできるか、どの方法で
kero pr merge 123 --squash --delete-branch
```

`kero pr review` にはアプリが開いていることが必要で、[Ama](./ama.md) が実行するとき以外はリモート操作も必要です。エージェントが下書きのレビューとガイドを書き、プルリクエストを操作するためのコマンドは[コマンドライン](./cli.md#draft-reviews)にあります。
