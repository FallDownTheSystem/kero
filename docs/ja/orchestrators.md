# オーケストレーター

オーケストレーターは、作業を計画し、そのための別のセッション（**子**）を開始して見守るエージェントセッションです。あなたが話しかけるのはオーケストレーターだけです。

## 始める

[新規セッションのダイアログ](./sessions.md#new-session-dialog)で **統括役** と任意の **目標** を選ぶか、次のように開始します:

```sh
kero new --orchestrator --goal "新しいログインページを出す"
kero new -p api --orchestrator --goal "新しいログインページを出す" -- codex   # default-agent 以外のエージェントで
kero orchestrator <session>       # セッションをオーケストレーターにする（off で元に戻す）
```

`kero orchestrator <session> off` は普通のセッションに戻し、その子は独立したセッションになります。

## 役割プロンプトとエージェント

選んだエージェント（なければ `default-agent`）は役割プロンプトから始めます: 計画して、自分のサブエージェントか `kero new` で開始する子のうち、仕事に合うほうに任せる（単独で出荷できる部分ごとに子を 1 つ）、続きの依頼は新しい子を始めず、その仕事をすでに持つ子に `kero message` で送る、どの子にも同じ構成のブリーフを渡す（あなたの言葉のままの目標、決まったこと、ファイルやリンク、完了の姿とその確かめ方、最後に送る報告）、各子には決定を自分のセッションのページであなたに示させ、決定が待っているときに報告させる、決定を中継せず、どのセッションが待っているかだけをあなたに伝える、複数の部分からなる仕事は 1 つの統合役を通し、すべての部分が報告してから、正確な操作をあなたに尋ねたうえで出荷する（「3 つの PR をマージして v2.2.0 をタグ付けしますか?」）、マージ済みの子や出荷するものがない子は閉じる、答えられることは自分で答え、必要なことだけあなたに尋ねる、対応の要らない報告には要約せず「OK」とだけ返す、あなたへの返答は短く、結果を先に、次に必要な 1 つの判断を、目標を見失わない。詳しくは kero スキルの `reference/orchestrating.md`（`kero skill show orchestrating`）にあり、プロンプトは子を始める前にそれを読ませます。プロンプトは **設定 › エージェント › オーケストレーター**（`orchestrator-prompt`）で置き換えられます。`{goal}` は目標、`{agent}` は既定のエージェントです。 どのエージェントを使う場合でも、オーケストレーターのエージェントだけに `--model opus` のような引数を渡すには、同じ場所の **引数**（`orchestrator-agent-args`）を設定します。Kero はオーケストレーターの開始時と再開時に、それをエージェントのコマンドの後ろに付けます。

## 子、報告、サイドバー

- **子。** オーケストレーターが `kero new` で開始したセッションはその子になり、同じプロジェクトに入ります。階層は 1 段だけです: 子の `kero new` は孫ではなく、同じオーケストレーターの別の子を開始します。`kero new --parent <session>` でオーケストレーターを指定し、`--parent none` でどれにも属さないセッションを開始します。`orchestrator-max-children` で同時に動く子の数を制限できます。オーケストレーターは `kero message <child> "<text>"` で子に答えたり指示したりします。子はそれをオーケストレーターからのメッセージとして読みます。`kero prompt` は、子がプロンプトで尋ねる質問や許可に答えるときだけ使います。
- **子を再開する。** 子の会話を `kero resume`、履歴、または再起動やクラッシュ後の Kero による復元で再開すると、そのオーケストレーターが開いていて空きがあるかぎり、再びその子になります。オーケストレーターやその子から実行した `kero resume` は、`kero new` と同じく再開したセッションをその子にし、`--parent <session|none>` も受け付けます。すでに開いているセッションは `kero parent <session> [orchestrator|none]` で子にする（オーケストレーターのプロジェクトに移ります）か、トップレベルのセッションに戻せます。
- **報告。** 子が入力待ちになる、作業のあとアイドルになる、失敗する、終了する、閉じられると、Kero はオーケストレーターがプロンプトに戻ったときに、入力中のあなたの内容には触れず、エージェント自身の[受け取り方法](./agents.md#how-agents-get-keros-messages)でメッセージを送ります。近いタイミングのものは 1 つのメッセージにまとめ、2 秒未満の状態は報告しません。子は `kero report --to-parent "<報告>"`（標準入力からなら `-`）で自分の結果を送れます。Kero のフックが子に示すスキルの `reference/reporting.md` は、報告を 4 つの部分で求めます: **Result**（結果と、その証拠）、**Not done**（やっていないことと、あなたが覆したいかもしれない前提）、**Where**（ブランチ、コミット、プルリクエスト、URL）、**Next**（次に取るべき正確な操作と、誰が取るか）。行き詰まった子は、できることをすべて終えてから「Waiting on you:」で始まる報告を送ります。子は `kero report working|done|blocked` でサイドバーの行も最新に保ちます。オーケストレーター自身が閉じた子は報告しません。報告はオーケストレーターがプロンプトに戻るまで待ち、その間に閉じられた子の状態の行は取り除かれます。閉じられたことと、子が送った要約だけが届きます。
- **子のターン。** Claude Code、Codex、Pi、OMP の子がターンを終えると、その報告にはターンの最後の返答が入ります。バックグラウンドで動き続けているもの（例:「1 shell, 1 monitor still running」）も伝えます。ターンの終わり、返答、バックグラウンドの作業は、ターンが終わるときにエージェントの[フック](./agents.md)が Kero に伝えます。フックがない場合（中断されたターンや他のエージェントなど）は、Kero が子の画面からターンの終わりを判断し、返答をエージェントのトランスクリプトから読みます。API エラーなどで失敗したターンは、そのエラーとともに報告されます。長い返答は最初と最後の約 1,000 文字だけが入り、`kero read <子> --reply` で全文を表示できます。新しい返答のないターン（会話を圧縮しただけのものなど）と、子が `kero report --to-parent` で終えたターンは、バックグラウンドで動いているものがなければ報告しません。子が報告を送ったあとも作業を続けた場合は、ターンの最後の返答が届きます。子には最後の返答がオーケストレーターに届くことが伝えられるので、子はターンを結果か質問で終えます。
- **サイドバー。** オーケストレーターの行には印が付き、ツールチップに目標が出ます。子は移動しても常にそのすぐ下に ↳ 付きで並びます。シェブロンで子を折りたためます（Kero が覚えます）。折りたたむと、対応が必要な子の数を表示します。
- **通知。** 子の変化はサイドバーに出ますが、通知せず、Dock のバッジにも数えません。それはオーケストレーターが受け取ります。オーケストレーター自身の入力待ちとエラーは通常どおり通知します。`notify-children`（**設定 › 通知**）で子の通知を戻せます。
- **子に直接話しかける**こともできます。クリックして入力するだけです。オーケストレーターは次の報告でそれを知ります。
- **閉じる。** オーケストレーターを閉じると、子も閉じるか、独立したセッションとして残すかを尋ねます（`kero close <orchestrator> --children` は子も閉じます）。専用のワークツリーを持つ子は、それを[整理](./worktrees.md#cleaning-up-worktrees)に任せて残します。子を閉じるとツリーから外れ、ワークツリーの子はいつもどおりワークツリーについて尋ねます。

`kero ls` はオーケストレーターと子に印を付け、`kero status <orchestrator>` は目標と子を、`kero status <child>` はそのオーケストレーターを表示します。
